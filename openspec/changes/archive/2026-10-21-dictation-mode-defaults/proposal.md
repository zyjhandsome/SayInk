## Why

全新安装和日常切换时，单次转写、持续转写、会议的分工是合理的，但结果去向、粘贴目标和首装缺模型的引导，会让用户觉得「默认行为变了」或「说完不知道字去哪了」。这次按人实际使用的顺序，把这三处默认体验对齐。

## What Changes

- 单次转写和持续转写各自记住「结果去向」。两者的初始值都是「自动（随音源切换）」：麦克风输入当前光标并保存历史；电脑声音或混合音源只保存历史。一种模式里的手动选择不再改另一种模式。
- **BREAKING**：今天两种模式共用 `output.mode`。升级时只迁移一次：已保存的录制方式保留当时的明确选择；另一种回到自动。当时已是自动的，两种都保持自动。
- 准备粘贴时，以「开始说这段话时」的前台窗口为目标。输出时窗口已经变了，就不发送粘贴键，文字留在剪贴板并提示。持续转写要让用户看见当前这段准备输入到哪个应用。会议仍然不向其他应用粘贴。
- 轻量安装、本机没有主识别模型时，首次启动直接进入准备页：下载模型 → 测试麦克风 → 试说一句。不等待约 15 秒的欢迎兜底。AI 润色和会议纪要仍留到用户需要时再配置。
- 普通转写在「历史已关闭」且当前结果只会进历史时，开始录制前必须让用户选择开启历史或改结果去向。会议记录继续独立保存。
- 会议进行中或暂停时，已经写入文字稿的段落可以改字。正在识别、尚未落段的内容不能改。结束收尾和纪要生成期间仍不能改。会后编辑规则不变，并改掉「必须等纪要生成完才能改字」这句与实际不符的提示。

## Capabilities

### New Capabilities

- `dictation-mode-defaults`: 单次/持续转写的分模式结果去向、粘贴目标绑定、缺模型首装准备、「只记历史但历史已关闭」时的开录前选择，以及会议进行中对已落段文字的修改。

### Modified Capabilities

- 无。现有 `openspec/specs/` 没有覆盖结果去向、首装引导或粘贴目标。

## Impact

- 配置：`sayink/config.py` 的 `output.*`；已有 `config.json` 的读取兼容。
- 输出：`sayink/app.py` 的 `_output_text`、`sayink/text_paster.py` 的 `paste_async`。
- 界面：`sayink/ui/settings_pages/general.py`、`sayink/ui/settings_window.py`、`sayink/ui/dictation_hints.py`、`sayink/ui/main_window.py`、`sayink/ui/floating_window.py`、`sayink/onboarding.py`、`sayink/ui/meeting_page.py`。
- 会议文字：`sayink/meeting_session.py` `save_segment_text`、`sayink/meeting_store.py` `set_segment_text`。会议仍不把文字稿粘贴到其他应用。
- 不把 Fun-ASR-Nano 打进轻量包，不改快捷键、不改默认音源、不默认打开 AI。

# 口述模式默认体验：需求与代码事实简报

## 意图

### 目标与成功标准

- 目标：让全新安装后的单次转写、持续转写和会议，按用户心里已有的用途工作；切换模式或音源时，不把上一种用途的结果去向偷偷带到下一种。
- 可观察的成功结果：
  1. 无旧配置、模型已就绪时，单次转写仍是麦克风、按住 `Alt+X`、松开后把整句输入当时开始说话的那个窗口，并写入历史；默认不润色。
  2. 持续转写仍是按住 `Alt+X` 开始、松开后继续、按停顿分段输入；默认同样输入开始说该段时的窗口。改成电脑声音或混合音源后，只保存历史。
  3. 在持续转写里把结果去向改成「仅保存历史」后，再切回单次转写，单次转写恢复为自动（麦克风仍输入光标），不被持续转写的选择带走。
  4. 在记事本开始说话、识别期间切到聊天窗口时，文字不进入聊天窗口；剪贴板保留这段文字，并提示原来的目标。
  5. 轻量安装、没有主模型时，主窗口出现后直接看到准备页，而不是先等约 15 秒再看到「去下载模型」。
  6. 历史关闭且结果只会进历史时，按下录音不会开始；用户先选择开启历史或改为输入光标。会议记录不受这次选择影响。
  7. 会议进行中或暂停时，已经出现在文字稿里的段落可以修改文字；原文、时间和发言人保留。还没写进文字稿的当前句不能改。会议结束收尾或正在生成纪要时不能改。

### 边界与非目标

- 本次范围：分模式结果去向、粘贴目标绑定与提示、缺模型首装准备页、开录前的历史冲突选择、会议进行中修改已落段文字。
- 非目标：
  - 不改变三种模式的职责：单次短句输入、持续口述、会议整场记录。
  - 不把会议文字稿粘贴到其他应用，不改变会议的开始、暂停、结束和 Esc 行为。
  - 会中改字只针对已经落段的文字，不改尚未识别完成的当前句，也不在收尾或生成期间改字。
  - 不把 Fun-ASR-Nano 打进默认轻量安装包，不改变完整包「模型已在、加载完即可用」的路径，除「模型已在时仍用现有欢迎」这一保持项。
  - 不在首装准备页配置 AI 服务。
  - 不改变默认音源、默认快捷键、默认关闭润色、会议默认混合音源。
  - 不重做历史库、会议库或识别模型。
- 禁止修改路径：安装包是否捆绑主模型的打包开关；会议记录的存储隔离；鉴权、支付、凭据管理器中的 API Key 存取。

## 代码事实

### 现状摘要

三种模式的职责和全新安装的主路径已经按「短句输入 / 连续口述 / 整场记录」分开，这一层是合理的。别扭出现在模式之间共用的结果去向、粘贴发生的时机，以及缺模型时的第一眼。

事实：没有配置文件时，`Config._load` 把 `first_run_welcome_seen` 写成 false，从而出现欢迎。默认 `audio.input_source` 是 `microphone`，`audio.trigger_mode` 是 `hotkey`（单次），`meeting.input_source` 是 `mixed`，`llm.enabled` 是 false，`history.enabled` 是 true。`output.mode` 默认 `paste`，`output.follow_input_source` 默认 null；null 且当前是粘贴时，`output_follows_input_source()` 为 true，所以麦克风保持输入光标，电脑声音或混合音源会被改成只记历史。

事实：单次与持续共用这一份 `output.mode`。设置里只有一个「结果去向」组合框，选项是自动、输入当前光标、仅保存到历史。手动选择会把 `follow_input_source` 写成 false，之后切换音源不再改它，切换录制方式也不另存一份。

事实：会议行在 `_output_text` 里和「只记历史」走同一条「不粘贴」分支，但是否写入由会议记录自己的保存决定，不看普通转写历史开关。`history_only_output()` 为 true 且 `history.enabled` 为 false 时，仍会录完，然后浮条显示「未保存 · 历史已关闭」。设置页和转写提示会把这句写成红色警告，但不阻止开始。

事实：`TextPaster.paste_async` 在准备粘贴时才读取前台窗口。延迟发送前若焦点变了，会保留剪贴板并回报 `focus_changed`。`_on_recording_start` 没有记录开始说话时的窗口。因此「在记事本按下快捷键、识别期间切到聊天窗口」会把聊天窗口当成目标。

事实：欢迎由模型 `ready` 或 15000 毫秒兜底触发。缺模型时文案要求去「设置 → 引擎」下载，并提供「去下载模型」。默认打包不包含 Fun-ASR-Nano，完整包才包含。模型已就绪时，欢迎说明按住快捷键，并提示先把光标放到要输入的位置；历史是否开启是下一项单独提问。

推断：用户会把「单次」理解成随时对当前光标说一句，把「持续」理解成同一篇稿子说很久，把「会议」理解成这场的记录不该突然出现在别的软件里。共用一份结果去向，违反的是第二种和第一种之间的切换预期，不是音源自动切换本身。

### 可复用 / 需扩展 / 冲突

#### 可直接复用

- `follow_input_source_for_output` 的音源规则：`system` / `mixed` → 历史，其他 → 粘贴。
- `paste_async` 已有的「焦点变了就不发粘贴键、保留剪贴板」。
- 会议行不进入粘贴器。
- `dictation_hints` 与通用页红色警告的文案条件：只记历史且历史关闭。
- 模型下载入口 `show_main_window("engine")` 与现有模型卡片。

#### 需要扩展

- 结果去向从一份变成单次、持续各一份，设置组合框随当前录制方式读写对应的一份。
- 录音开始（单次按下时；持续转写按开放问题决定的时机）记录目标窗口句柄与进程名，输出时交给粘贴器比较。
- 持续转写的浮条或主界面显示当前输入目标。
- 缺模型的首装改为立即可见的准备页，而不是等待兜底的消息框。
- 开始单次或持续录音前，若当前有效结果无处可去，先完成选择。

#### 需求与现状冲突

- 现状故意让手动结果去向跨音源、跨模式保持。新的预期是跨模式不要保持。音源自动规则在「自动」下仍然保留。
- 现状把「输出前的短延迟内焦点没变」当作粘贴安全。新的预期是「从开始说话到输出，目标窗口没变」。
- 现状允许「历史关闭 + 只记历史」录完再提示未保存。新的预期是还没录就把这个死路选完。
