# 三种模式的公共识别能力

2026-10-23 增补：三种模式已加入短续音保护、原文保留和取消时的原生解码互斥。
轻声增强、跨段上下文、混合音源分别识别及本机录音恢复均有独立开关，默认关闭。
实现、收益及限制见 [最终验收](recognition-optimization-completion-20261023.md)。

本文按实际代码说明单次转写、持续转写和会议的公共能力，以及各模式的会话和输出行为。模式名称及相关用语遵循 [术语规范](terminology.md)。

## 保留模式边界

- 单次转写由松开快捷键结束，内部提前识别的片段保留在转写条上，最终统一输出；公共 VAD 不改变快捷键语义。
- 强制切分后的续音不再套用独立短噪声的最短时长过滤；立即结束时，可从起音缓存恢复紧接切点的短有声尾部。真实停顿后取消续音保护，独立短噪声仍过滤。App 接收分段器输出时不再增加 100 ms 时长过滤。切点、神经 VAD 重置及原始采样时间保持原规则；默认没有跨片段重复音频，不使用文本猜测去重。主动开启实验性跨段上下文时，仅支持带可靠词元时间戳的 CTC 引擎，原始采样范围不变；校验不通过就识别原片段。两份实际评测没有证明精度提升，故默认关闭。
- 清洗只移除引擎标记，重复表达及混合语言保留；历史原文在术语误写替换及大小写还原之前固定，输出变化单独保留。
- 文字长度超出宽松的音频承载预算且短语循环至少 8 次时，使用覆盖全部原音频的两个短片重新识别，交接处保留少量重叠并使用现有拼接规则。最多两次额外解码；候选为空、仍过长、异常或取消时保留首次文字。不凭重复次数直接删除内容，普通重复和数字不触发额外解码。
- 持续转写和会议在当前润色或粘贴期间最多预识别队首一段，仍使用同一原生识别工作槽。预识别不改当前文字、历史、说话人归属或输出状态；缓存结果轮到输出时才提交，失败保留音频走正常识别。队列清空同时取消预识别，迟到结果不能恢复旧队列。输出完成后的调度不再额外等待 300 ms。
- 持续转写按停顿输出，结束后处理收尾与排队片段。
- 会议使用独立会话状态、暂停/恢复、参与人、标记、纪要和导出；内容不自动粘贴。
- 会议文字稿始终保存，不随转写历史清理；不能把二者强制套用同一个保留策略。
- 录音恢复默认关闭，开启后才在本机保存 VAD 前原声，混合来源额外保留两条原始音轨；恢复窗支持导出与本机重新识别。音频与文字历史分别清理，声纹仍不落盘。缓存健康时允许磁盘排队、继续监听；写入失败及空间用尽时保留原有暂停保护，暂停期间不能补录。
- 会议默认不逐句润色，避免改写发言与增加处理延迟。纪要模板、输出语言和发言人更正属于会议能力。
- 会议与持续转写共用谨慎的说话人判断。证据不足时保留未知，不沿用上一人；
  会议文字稿显示「说话人待确认」，持续转写历史中已识别人声与未知段并存时也明确标出待确认。
  会中人工纠正可用本场近期清晰声音帮助后续匹配；持续转写不新增人工更正入口。
  真实收益用 `meeting_speaker_bench.py` 与 `asr_bench.py` 对照，见两份评测文档。
- 片段内换人分析得不出稳定单人结论时（窗口不稳、分界未经证实），整段仍按整段声纹去匹配
  已有档案：只接受强匹配且带余量的结果，不新建编号、不更新档案；匹配不上才待确认。
  检测到重叠或多人混合的部分不参与匹配，继续待确认。
- 一场结束时（会议 `finalize`、持续转写排队处理完），对本场**全部**发言的声纹做一次平均连接
  层次聚类，并**逐段**重新归属（`speaker_clustering.reassign_turns`）：在线匹配时被拆成多个
  编号的同一个人会合并，卡在错误组里的单句会移到正确的人；不足 3 段且不足 8 秒的小簇并入
  最近的人。用户命名或更正过的编号保持不变，锁定的段不会移动；没有逐段证据时退回原有的
  质心合并。合并阈值由声纹后端给出（CAM++ 0.60、频谱 0.75）。
- Silero 断句的语音概率门限为 0.25（原 0.5，第五轮 0.3）：真实会场里最轻声的人有一到两成
  的发言在 0.25–0.5 之间，按高门限会整句切掉或并进静音；0.2 开始吐出房间噪声，不再有收益。
  能量门限仍是底线，数字静音不会被打开。
- 自定义词汇的一行可以写成 `词=误写1、误写2`：等号后是识别器常把这个词写成的样子。每个最终
  结果在 `normalize_asr_output` 与英文大小写还原之后、送润色 / 纠错 / 粘贴之前，把出现的误写
  按最长优先一次性替换为正确写法（英文整词、不分大小写；中文原样匹配，不再扫描替换结果）。
  热词仍只传正确写法，`variants` 不进热词串。误写与另一条术语同名时跳过，避免两条互相改写。
- 「纠错」是润色的严格版：系统提示只允许改同音 / 近音错别字、切错的词和术语写法，用户消息附带
  术语表（`正确写法 ← 误写`）和最近 2 分钟内上一句输出的结尾（最多 120 字，只作参考）。温度 0；
  DeepSeek 官方 `deepseek-flash` / `deepseek-v4-pro` 关闭思考。回复要先过润色的保真检查，再满足
  压缩后长度在 0.85–1.15 倍（+4 字）以内、编辑距离不超过 max(2, 20%)，否则输出识别原文。
  会议逐句处理仍由 `meeting.polish_segments` 决定；关闭时会议行不经过纠错。
  远场会议 10 分钟摘录上 CER 变化在 ±0.3 个百分点内，见第七轮文档。
- 三种模式共用短句空结果重试：首次识别为空时，仅对有明显声音且不超过 8 秒的片段保留语音边界、
  补静音上下文重试一次。有效文字、纯静音、极低音量和较长片段不重试；重试失败仍继续收尾。
  单次转写可在录音过程中内部识别与重试，但仍等松开快捷键且全部片段处理完后统一输出。
- CAM++ 成功加载时，会议与持续转写共用后台片段内换人分析，按可靠边界分别转写；频谱回退
  保持原有分段。短促插话、重叠声音仍可能无法拆开。`meeting_turn_bench.py` 测换人边界，
  `asr_bench.py --speaker-turns off` 提供文字识别的关闭对照，默认统计开启分析时的实际耗时。
- 未开启多人发言检测时，若没有可靠换人切点，但多个清晰窗口反复呈现两组强烈冲突的声纹，
  整段保留给文字识别，人物待确认且不用于训练声音档案。这是保守的混合声音防护，不会分离
  人声，也可能将变化较大的单人语音标为待确认；短促接话和重叠仍可能漏检。
- 开启可选多人发言检测后，持续重叠及其不稳定过渡区间单独待确认，前后清晰部分仅匹配已有声音档案，
  不从这类恢复片段新建或更新档案。
  局部单人状态切换仅提供候选，须经 CAM++ 复核后才拆分；不足一秒的声音不建立或更新档案，
  只允许强证据匹配已有身份。新增切分可能改变识别文字，完整覆盖音频不等于词句必然无误。
- 混合采集在声道均衡前检查麦克风与电脑声音的波形相关性。仅对高度相关的延迟重复波形扣除
  播放声分量，保留剩余麦克风信号；明显双人同时说话时保留原混音。参考缓存最多 650 ms，
  每次录音重新开始，不作为人物身份依据。该检查不具备通用声学回声消除或双人分离能力。
- `meeting_timeline_bench.py` 对照独立 RTTM 标注，按音频时长统计正确、错误、待确认与短接话召回，
  重叠单列；同时给出标准 DER（10 ms 帧、0.25 秒 collar、一对一映射，待确认计为漏检）和按回合
  长度分组的归属正确数。默认固定 15 秒片段、不运行 VAD/ASR；`--segmenter silero` 改用会议实际的
  Silero 断句，`finalized` 一栏另行给出结束后逐段重新归属的成绩。它不测中文错字率；
  `textgrid_reference.py` 可把 TextGrid 逐字稿转成 `asr_bench.py` 的参考文本和 RTTM。
- CAM++ 会议与持续转写在同一会话内保留最多 2 秒内存声音作为相邻分段的分析上下文。
  仅在同一来源、同一模型且间隔不超过 50 ms 时复用，不把旧声音送入 ASR。
  有可靠声纹变化时可补充分界；过短的混合首段保留原文字边界、待确认且不训练档案。
  恢复片段只匹配已有档案，清空会话时清空上下文。
- 常规窗口未提出分界时，可复查相邻片段开头的短接话：仅处理原本允许判断且长 3.2–6 秒的首段，
  要求开头声音强匹配上一段、后续较长声音稳定且不同，并有相邻候选共同支持。
  恢复短段和后续段均不更新声纹；配置的局部多人检测否决时保留原 ASR 边界并待确认。
  这是有条件的短接话补充，仍不保证亚秒级发言或词级边界准确，见第四轮评测报告。
- `SpeechSegmenter.last_bounds` 与 `segment_meeting_timed` 保留原输入采样时间，含前置缓冲、停顿和保留尾音。
  `recognition_replay.py` 以相同时间轴运行后台转写，并生成本地音频核对页；无标注输入不会产生准确率指标。
- 持续转写拆分后的文字仍按顺序通过原有润色、粘贴或只记录流程，说话人标签只出现在历史。
  停止后继续处理已录内容，最后一段为空也完成收尾；立即重新开录时，上一场排队内容保留原场编号，
  不更改新场序号，也不向新场声音档案学习。关闭转写历史仍不会保存持续转写内容。

## 配置与状态

`recognition_settings.RecognitionSettings` 统一读取 `stt.*`，提供模型能力与热词/语言解析；会话获得配置快照，随后保存的设置不会修改这个快照。`audio_source` 统一解析 `audio.input_source` 与可选的 `meeting.input_source`。会议音源为空表示继承；升级保留原有显式值。

通用页将「识别」与「会议默认设置」分开。识别语言与自定义词汇直接可见；语音分段、Silero 下载和 CAM++ 增强位于「高级识别设置」。保存后待生效、语音检测加载失败等状态在折叠时仍可见。会议开始卡片的音源、模型、语言只作用于本场，不写回公共设置。CAM++ 开关明确只影响持续转写与会议的增强方法，关闭后仍使用原有频谱粗分。

`AudioRecorder.segmentation_status` / `segmentation_changed` 报告实际 gate。文件存在、用户选择、加载成功是三个不同事实。Silero 加载失败后使用能量法，界面保留失败提示；会议文字记录的断句方式也采用实际值。CAM++ 同样报告真实加载或频谱回退，辅助模型卡片只标「已下载」。

公共识别设置和模型更改在空闲时应用；录音、整场监听、会议或处理已录语音期间保存的更改标为待生效。当前断句器、声纹实例和队列继续完成本场，结束且队列处理完后统一应用最新设置。设备、触发方式等原有音频设置仍沿用已有设置流程；它们与公共识别设置的等待规则应分别按界面说明理解。

## 后续可评估

真实多人会议的说话人准确率、混合音源回声与串音处理、根据设备和录音样本推荐停顿节奏，均值得单独验证。本次先统一现有能力和可观测状态，不在缺少录音评测的情况下增加识别调参或声学处理。
