# 会议页阅读与纠错交互

2026-10-17，根据纪要与文字稿截图评估更新。保留已有会议录制、辅助模型、纪要生成确认与上一版恢复机制。

## 内容与操作范围

- 会议开始卡正文与实时笔记区可滚动，主要操作保留在滚动区外；小屏检查使用真实会议控制器，覆盖开始、进行中、暂停与整理状态。
- 侧栏显示本场会议音源与录制/暂停/整理状态；离开会议页仍可查看，结束后恢复转写提示。
- 可主动暂停采集；暂停期间不采集新音频，已录内容继续识别，只有用户继续才恢复采集，会议不分场。
- 实时文字稿刷新保留选区与阅读位置；原本停在底部且没有选区时跟随新发言。
- Ctrl+F 在会后列表搜索会议，在会议进行中查找本场文字稿；Enter 查找下一处并循环。无匹配会议时显示空状态和清除搜索入口。
- 默认状态解释说话人区分效果，模型与断句诊断放在悬停详情中。

- 纪要页复制已保存 Markdown，编辑时复制当前草稿；文字稿页复制带时间和发言人的完整文字稿，不以已生成纪要为前提。选中文字时保留原生局部复制。
- 导出分为仅纪要、仅文字稿、完整会议记录。编辑时纪要部分使用当前草稿，导出不会隐式替换已保存内容。
-「保存修改」明确保存；切换会议、离开页面、进入新会议流程时也会保存。保存失败保持原会议与编辑内容，并提示可复制草稿。

## 来源与模板

- 文档区显示 AI 生成 / 已手动编辑、所用模板。手动编辑不标记为已经核实。
- 模板下拉框选择的是下次生成的模板，刷新保留选择；选择与现有纪要不同时提示重新生成后生效。
- 重新生成沿用替换确认与上一版恢复；生成期间禁止编辑及发言归属纠正，避免结果覆盖正在修改的内容。
- 生成提示词区分发言者对身份识别的陈述与经过验证的系统能力；人名和声音分组均不作为身份验证证据。

## 说话人与单段更正

- 连续的同一说话人发言共用姓名标题，每段保留独立时间与引用锚点。手动姓名与自动声音分组有文字说明。
-「命名说话人」修改整组显示名称，沿用现有纪要名称更新逻辑。
-「纠正发言人」进入明确的纠正模式，在目标段落点「更正」，选择已存在的说话人或新增编号。对话框展示该段内容与作用范围。
- 录制中与暂停时均提供「命名说话人 / 纠正发言人」，实时姓名也可点击。说话人菜单在打开时刷新，避免新段落到达时改动正在操作的菜单。实时正文继续按段追加，改名与更正刷新时保留阅读位置和选区，不暂停采集。
- 会中命名作用于本组已有发言与后续归入本组的发言；单段纠正只改变这一段已有归属。
  保存成功后，本场近期的清晰声音可帮助判断后续发言，其他已有段落不被回写；短句或无效声音不训练档案。
  选择新增身份时预留编号，避免识别线程后来分配同号。保存失败保留选择；弹窗打开期间若会议结束或进入收尾，拒绝迟到的保存并提示重新选择。
- 声音证据不足或候选人相近时显示「说话人待确认」，不生成「说话人0」或默认改成说话人1。
  点击纠正后须主动选择归属，不预选第一位；可选择已有身份或新增身份。
  复制、导出、纪要输入保留待确认状态，不将不同的未确定段落当成同一人的发言。
- 会议收尾整理与纪要生成时禁用说话人修改。会中操作反馈单独显示，保留暂停原因或设备异常提示；新会议清除上一场的纠正模式、菜单和反馈。
- 按实际片段 `seq` 更新单段，不能使用显示列表索引代替；空段过滤不改变更新目标。仅修改该会议中 `trigger_mode = meeting` 的记录，日常转写不受影响。
- 纠正后保留纪要，记录其来源已更正并提示核对。重新生成清除当前版本的来源更正标记；恢复旧版时一起恢复那一版的标记。
- `meeting_notes` 新增 `transcript_changed` 和 `previous_transcript_changed`，旧库在启动时添加默认值，不改写已有文字或上一版。
- `history.speaker_locked` 单独记录人工确定的片段归属，旧库启动时添加默认值，保留文字修正。会后分组只更新未锁定的会议片段，不更新同场单次转写或持续转写的记录；已人工命名或人工归属使用的身份保持编号，两个已确认身份不自动合并。持续转写与会议共用谨慎匹配和后台换人分析，人工归属更正仍只在会议中提供。

## 文字稿正文纠错

- 会后文字稿每段旁提供「编辑」；按实际片段编号定位，空段不会导致修改错位。会议进行中或该场正在生成时不可编辑。
- 编辑弹窗显示时间和发言人，可查看修改前原文、恢复原文并明确保存。取消不写入；保存失败保留草稿，可重试或复制备份；空白内容不能保存。
- 人工修正单独写入 `history.corrected_text`，保留 `raw_text`、`polished_text`、时间和说话人。旧库启动时添加默认空字段，不改写已有内容。仅修改已结束或已中断会议的会议段落，不影响单次转写与持续转写的记录。
- 阅读显示「已修改」。纪要、原文精整、复制与导出优先使用修正内容，搜索匹配当前文字稿。恢复原文清除修正并回到修改前的读取规则。
- 已有纪要或精整正文不被文字编辑替换；当前版本与上一版都标记需要核对，提示重新生成。生成后的新版本清除当前来源更正标记，恢复旧版仍保留它的提醒。

## 引用与阅读

- 纪要引用跳转到对应文字稿并高亮；「返回纪要」恢复点击前的阅读位置。
- 相同内容刷新保留正文位置。短会时长使用自然语言，文字稿位置省略无意义的小时零位；导出继续保留完整时间戳。
- 空决策 / 待办章节仅在阅读视图合并为「暂未提取到明确内容」，原 Markdown 仍完整保留。
- 主列表默认收窄并保留可拖动分隔条；复制按钮预留足够宽度，避免切到文字稿后截字。

## 原文精整

会议模板「原文精整」将多人的口述讨论自然融合成通顺、逻辑清晰的书面文章。逐段逐句梳理与重写，仅去除口吃重复、纯粹口语赘词和无效寒暄，保留业务细节、情绪、主观评价、个人口吻、分歧及原文语言。按人物、业务规划和话题变化细分段落，不按说话人或识别切片机械分段，不反复用「某某表示 / 一方认为」串联发言，也不生成标题、摘要或列表。只有省略归属会混淆立场、经历或责任时，才做必要的自然区分。提示词包含保留具体业绩数据、强烈评价和扩招条件的成文示例。

选择该模板时操作改为「整理原文」；当前结果生成后，阅读页签、复制和导出使用「精整正文」。选择另一模板只影响下次生成，当前内容的名称仍依据已保存结果。

精整优先读取人工修正的文字稿，未修正片段从原始转写读取，独立于摘要 JSON 流程。输入正文分为不超过 500 字符的来源片段，每次最多处理 1600 字符；相邻块的少量上下文仅帮助衔接。内部 JSON 记录各段覆盖的来源编号，要求按顺序完整覆盖且不重复，显示和复制时仅保留正文。每块校验数字与单位、英文名称、否定及条件表达、明显压缩与过长段落；返回截断或校验失败时重试一次。全部成功才保存，不将部分结果替换已有内容，不进行二次总结。规则只能发现部分明显异常，不能证明语义完全无损。

上一版除正文外同步保留模板、模型、结构化结果及生成元数据。启动时为旧库增加默认空的元数据列，不改写已有文字；恢复时同步切换模板，避免从精整正文恢复纪要后仍显示精整操作。
