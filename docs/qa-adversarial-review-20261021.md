# 2026-10-21 红蓝对抗式全功能验证

范围：单次转写 / 持续转写 / 会议三条链路，历史、会议、通用、引擎、AI 服务、关于六个页面，浮动条与托盘，以及 `tools/` 下的评测脚本。
方法：先由"红方"按维度独立找问题并给出复现方式，再由"蓝方"逐条复核是否真是问题、是否值得改；确认的直接修复并补回归用例，不成立或有意为之的记录原因。
所有验证使用隔离配置、临时数据库和虚构文字；没有读取用户的历史或会议，没有录制环境声音。

## 验证维度

| 维度 | 具体看什么 |
| --- | --- |
| 功能正确性 | 链路每一步是否真的发生：录音 → 分段 → 识别 → 润色/纠错 → 粘贴/入库；会议开始、暂停、结束、纪要、重命名 |
| 逻辑性 / 关联性 | 状态机互相等待（死锁）、竞态（TOCTOU）、跨模块回调时序、看门狗兜底后状态是否复位 |
| 一致性 | 同一事物在托盘、浮动条、侧栏、设置页、会议页、README 的叫法与颜色；工具脚本与应用是否跑同一套策略 |
| 繁冗性 / 重复度 | 同一段逻辑写了几遍（分段器组装、说话人会话参数、重贴标签 SQL、空结果 UI 分支） |
| 清晰性 | 提示文字是否说对了原因（"录音过短"vs 无人声、"润色中"vs 纠错、不存在的设置路径） |
| 可维护性 | 死代码、只写不读的字段、互相必须相等却各自定义的常量、魔法延时 |
| 实用性 / 易用性 | Tab 顺序、可访问名、确认文字被立刻覆盖、API 密钥隐藏后仍可见、撤销窗口被悄悄放弃 |
| 鲁棒性（对抗） | 畸形配置、损坏数据库、超长 / RTL / 零宽 / 表情文字、极端窗口尺寸、LLM 返回 null / 非 JSON / 应答式文本、模型文件半截 |
| 安全边界 | API 密钥只经凭据库读取，不落盘、不进日志、不进命令行；安装包不会带入未提交文件 |

## 在线服务使用

R1 的 A/B 两组中复现 LLM 相关问题（应答式回复、null 字段、非 JSON）用的是本地假客户端，没有调用付费接口。
同一会话早先的识别准确率评测（`docs/recognition-optimization-round*.md`）通过 `tools/asr_bench.py --llm-correct` 调用了 DeepSeek 纠错，累计约 6 万 token；密钥只在进程内经 Windows 凭据库读取，未写入文件、日志或命令行。本文档对应的验证轮次没有新增 API 调用。

## 未覆盖范围

没有做真实麦克风 / 系统回放的长时采集、多小时模型推理、跨应用真实粘贴、安装包升级。音频后端差异（D10）只在逻辑上统一，实机不同声卡的电平仍需使用中观察。
R2 的时间数字来自一台同时在跑回归的机器，用于相对对照，不是延迟上限。
