# 说话人拆人 / 并人标定

会议纪要会按说话人写发言摘要和待办负责人。聚类阈值还没有用真人会议标定。
在本文件的结果表填上数字之前，对外口径保持 README 的「实验性」：设置里写明
不验证人物身份，会议页写明姓名来自手动命名。

「（待核对）」只标记文字稿里找不到的日期和金额，挡不住「同一个人被拆成两个编号」。
所以这张表是单独的尺子，不能用纪要里有没有「待核对」来代替。

## 标什么

至少 **3 段**已经结束的双人以上会议。音频留在仓库外，脱敏后再标注。
每一行是文字稿里的**一段**（一次识别切片），不是纪要里的一节。

```
序号	真人	预测
1	甲	1
2	甲	1
3	乙	2
```

- **真人**：听录音填写的人。同一个人全程用同一个代号。看不清就不要猜，删掉这一行。
- **预测**：SayInk 给出的说话人编号（改名之前的编号）。手动改名、单段纠正之后的结果不要拿来填这张表，那测的是人手，不是聚类。

用 CAM++ 跑一场，再把说话人增强关掉用频谱法跑同一段录音，各填一份。两份都要有，才能判断嵌入模型是否比频谱法少拆、少并。

## 怎么算

`tools/speaker_eval.py` 只读这张表，不读音频，也不加载声纹模型。

```powershell
py -3.10 tools/speaker_eval.py D:\bench\meeting-01-campplus.tsv
```

- **拆人**：某个真人的各段用了多于一个预测编号。拆人率 = 被拆的真人人数 / 真人人数。
- **并人**：某个预测编号下面有多于一个真人。并人率 = 这种编号的个数 / 预测编号个数。
- 一个人对应一个编号、不同人编号不同：两项都是 0。
- 空表没有比率。
- 预测为 `0`、`unknown` 或「待确认」表示暂不判断，不作为共同的说话人编号。
  同时报告待确认率与覆盖率（已归属片段 / 全部片段）；必须连同拆人率、并人率一起看，
  不能通过把困难片段都留空来宣称准确率提高。

设计成功标准 3 要求：嵌入模型的拆人率和并人率都明显低于同一批录音上的频谱法。
「明显低于」在有第一批数字之前不改写成某个百分比。

## 2026-10-20：稳定判断策略与可重复对照

会议与持续转写共用 `MeetingSpeakerSession`。零向量不再沿用
上一位；相近候选人差距不足时保留 `speaker_id = 0`。会议文字稿、复制、导出和纪要输入都
显示「说话人待确认」。这些片段可能来自不同人，提示词禁止将它们当成同一人或推断负责人。

清晰片段才可建立或更新声音档案：至少一秒非静音、数据有效且无严重削波。
每人最多保留 12 段代表声音，保留最初样本并淘汰较重复的样本；弱匹配与连续性猜测
不更新档案。连续性需要至少两段可靠样本、短时间间隔和候选人差距，未知段会中断该链。
超过自动人数上限时暂不归属，不强行塞入最接近的人。

只有数据库保存成功后，会中人工纠正才用于学习最近 512 个观察中对应实际 `seq` 的
清晰声音。原档案中的这条样本会移除；人工确认样本优先于重复的自动分组。
人工证据互相冲突时仍待确认。短、静音或无有效特征的段落仅修正文字稿，不训练声音。
档案与特征仅在本场内存中存在，结束或开始下一场不复用。

这是一轮规则与数据流改进，阈值仍待真人标定；清晰度检查不能检测重叠发言。
第一轮未加入无停顿换人分段、重叠分离或跨会议识人，不用单元测试代替声学评测。

新增 `tools/meeting_speaker_bench.py`，对同一组按时间排列的真人短录音同时跑旧策略与新策略，
共用实际嵌入结果并保留真实时间间隔：

```json
{"clips": [
  {"audio": "a-01.wav", "speaker": "A", "start_ms": 0, "case": "initial"},
  {"audio": "b-01.wav", "speaker": "B", "start_ms": 4000, "case": "rapid_turn"},
  {"audio": "a-02.wav", "speaker": "A", "start_ms": 1800000, "case": "returning"}
]}
```

```powershell
py -3.10 tools/meeting_speaker_bench.py D:\bench\meeting.json --backend campplus --out D:\bench\campplus.json
py -3.10 tools/meeting_speaker_bench.py D:\bench\meeting.json --backend mel --out D:\bench\mel.json
```

路径相对清单；`route` 可选 `mic` / `system`，未知时留空。显式选择 CAM++ 而加载失败会报错，
避免把回退结果写成 CAM++。输出包含实际后端、逐段判断、场景分组、拆人/并人/待确认率、覆盖率
和嵌入加匹配的实时率。音频须预先标成单人发言；本工具不测一段内的换人边界，也不输出 DER。
声音重叠、未切开的多人片段另做时间对齐标注评测，不混入这份单人片段表。

## 第二轮：片段内换人检测（实验性）

2026-10-20 后续已加入跨来源谨慎匹配、会后防链式合并，以及默认关闭的多人发言检测。
具体行为、覆盖率下降与漏检限制见 [本轮优化验证](recognition-optimization-20261020.md)。

CAM++ 实际加载成功时，会议与持续转写在后台对每个最多 15 秒的已采集片段分析换人位置，
再分别转写、编号与归档。频谱回退不启用该分析。
窗口 1.2 秒、步长 0.4 秒；两侧各需相邻窗口支持稳定声音状态，并且两种状态明显不同。
先修正跨换人窗口产生的混合锚点，再选择较安静的近邻位置切开；保留每个原始采样点，
不复制或删除边界音频。局部标签不占用本场说话人编号，最终仍由本场声音档案判断 A→B→A。

短窗只提出候选位置；左右还需各至少 1.6 秒、至多 3 秒的较长语音再次支持换人，
避免把同一人的不同字音、笑声或语气变化当成新说话人。仅有不稳定短窗时保留完整片段，
不凭局部聚类数量强行标成多人。较长证据仍不足的候选位置保留待确认。

没有可靠边界但存在不同声音证据时，说话人待确认且不更新档案。
声音过短、同时说话、音色相近、噪声与音乐仍可能漏检或误检；分段时间是近似值，
不是逐字对齐。此功能不分离重叠声音，也不跨会议保存声纹。

分析、特征提取与转写在现有可取消识别线程内完成，采集界面无需等待声纹推理。
拆出的内容通过普通输出流程保存，排在后来采集的语音之前；只移动尚未保存的队列编号。
已保存的段落、人工修改与 `seq` 不被回写。暂停与收尾继续等待当前后台任务；过时结果忽略。
分析失败或返回的分段未完整覆盖输入时，保留整段音频用于文字识别，说话人待确认。
混合音源的一整段主导来源不能代表每个子段，发生换人拆分时不虚构每位说话人的音源。

用 `tools/meeting_turn_bench.py` 单独测边界，原始片段不超过 15 秒：

```json
{"recordings": [{"audio": "a-b-a.wav", "boundaries_ms": [3200, 6400], "case": "rapid_turn"}]}
```

```powershell
py -3.10 tools/meeting_turn_bench.py D:\bench\turns.json --out D:\bench\turns-result.json
```

输出实际后端、预测边界、漏检、误切、精确率/召回率/F1、匹配误差与实时率。
默认容差 500 ms，必须在结果中保留容差；无换人片段也应纳入以检查误切。
本工具不计算 DER，不把只测边界等同于身份归属或文字准确率。

## 第五轮：真实会议 DER 基线

上面的 TSV 标定表靠人工听录音；有公开的人工说话人标注时，直接用
`tools/meeting_timeline_bench.py` 跑完整的会议说话人链路并算 DER，不必再手填。
AISHELL-4（中文真实会议室、远场阵列录音、官方 RTTM + TextGrid）是现成的来源；
音频与标注留在仓库外，manifest 指向 wav 与 RTTM（`uri` 为 RTTM 第二列）：

```json
{"recordings": [
  {"audio": "S_R004S03C01.ch0.wav", "rttm": "S_R004S03C01.rttm", "uri": "S_R004S03C01"},
  {"audio": "M_R003S04C01.ch0.wav", "rttm": "M_R003S04C01.rttm", "uri": "M_R003S04C01"}
]}
```

```powershell
py -3.10 tools/meeting_timeline_bench.py D:\bench\aishell4\manifest.json --segmenter silero --finalize on --out D:\bench\aishell4\timeline.json
```

`--segmenter silero` 用会议实际的 Silero 断句（而不是固定 15 秒片段），`finalized` 是
一场结束时逐段重新归属后的成绩。每个文件、每个阶段都有两套分数：

- 时长分数（原有）：单人时长里判对 / 判错 / 待确认的比例，重叠与非语音单列，不带 collar。
- `der`：标准 DER，10 ms 帧、参考边界两侧各 0.25 秒不计分、预测编号与真人一对一最优映射；
  待确认和分割器没吐出的语音都算漏检。`der.turns` 按参考回合长度（<0.8 s、<1.6 s、<3 s、≥3 s）
  统计回合内多数编号是否映射到正确的人，`missed` 表示回合内没有任何编号。
  同一个人出现在两个编号时只有一个编号能映射到他，另一个全算混淆，所以"拆人"直接体现在 DER 里。

结果写在 [第五轮优化记录](recognition-optimization-round5-20261020.md)（Silero 0.3）和
[第六轮优化记录](recognition-optimization-round6-20261020.md)（Silero 0.25，含帧级分割对照的上限测量）。
两场会议、单路远场通道的绝对数值不代表近讲麦克风或线上会议；相对比较（改动前后、实时与结束后）有效。
