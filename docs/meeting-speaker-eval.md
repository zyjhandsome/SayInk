# 说话人拆人 / 并人标定

会议纪要会按说话人写发言摘要和待办负责人。聚类阈值还没有用真人会议标定。
在本文件的结果表填上数字之前，对外口径保持 README 的「实验性」：设置里写明
不验证人物身份，会议页写明姓名来自手动命名。

「（待核对）」只标记文字稿里找不到的日期和金额，挡不住「同一个人被拆成两个编号」。
所以这张表是单独的尺子，不能用纪要里有没有「待核对」来代替。

## 标什么

至少 **3 段**已经结束的双人以上会议。音频留在仓库外，脱敏后再标注。
每一行是文字稿里的**一段**（一次识别切片），不是纪要里的一节。

```
序号	真人	预测
1	甲	1
2	甲	1
3	乙	2
```

- **真人**：听录音填写的人。同一个人全程用同一个代号。看不清就不要猜，删掉这一行。
- **预测**：SayInk 给出的说话人编号（改名之前的编号）。手动改名、单段纠正之后的结果不要拿来填这张表，那测的是人手，不是聚类。

用 CAM++ 跑一场，再把说话人增强关掉用频谱法跑同一段录音，各填一份。两份都要有，才能判断嵌入模型是否比频谱法少拆、少并。

## 怎么算

`tools/speaker_eval.py` 只读这张表，不读音频，也不加载声纹模型。

```powershell
py -3.10 tools/speaker_eval.py D:\bench\meeting-01-campplus.tsv
```

- **拆人**：某个真人的各段用了多于一个预测编号。拆人率 = 被拆的真人人数 / 真人人数。
- **并人**：某个预测编号下面有多于一个真人。并人率 = 这种编号的个数 / 预测编号个数。
- 一个人对应一个编号、不同人编号不同：两项都是 0。
- 空表没有比率。
- 预测为 `0`、`unknown` 或「待确认」表示暂不判断，不作为共同的说话人编号。
  同时报告待确认率与覆盖率（已归属片段 / 全部片段）；必须连同拆人率、并人率一起看，
  不能通过把困难片段都留空来宣称准确率提高。

设计成功标准 3 要求：嵌入模型的拆人率和并人率都明显低于同一批录音上的频谱法。
「明显低于」在有第一批数字之前不改写成某个百分比。

## 2026-10-20：稳定判断策略与可重复对照

会议使用 `MeetingSpeakerSession`，连续听写保留原有策略。会议中的零向量不再沿用
上一位；相近候选人差距不足时保留 `speaker_id = 0`，文字稿、复制、导出和纪要输入都
显示「说话人待确认」。这些片段可能来自不同人，提示词禁止将它们当成同一人或推断负责人。

清晰片段才可建立或更新声音档案：至少一秒非静音、数据有效且无严重削波。
每人最多保留 12 段代表声音，保留最初样本并淘汰较重复的样本；弱匹配与连续性猜测
不更新档案。连续性需要至少两段可靠样本、短时间间隔和候选人差距，未知段会中断该链。
超过自动人数上限时暂不归属，不强行塞入最接近的人。

只有数据库保存成功后，会中人工纠正才用于学习最近 512 个观察中对应实际 `seq` 的
清晰声音。原档案中的这条样本会移除；人工确认样本优先于重复的自动分组。
人工证据互相冲突时仍待确认。短、静音或无有效特征的段落仅修正文字稿，不训练声音。
档案与特征仅在本场内存中存在，结束或开始下一场不复用。

这是一轮规则与数据流改进，阈值仍待真人标定；清晰度检查不能检测重叠发言。
本轮未加入无停顿换人分段、重叠分离或跨会议识人，不用单元测试代替声学评测。

新增 `tools/meeting_speaker_bench.py`，对同一组按时间排列的真人短录音同时跑旧策略与新策略，
共用实际嵌入结果并保留真实时间间隔：

```json
{"clips": [
  {"audio": "a-01.wav", "speaker": "A", "start_ms": 0, "case": "initial"},
  {"audio": "b-01.wav", "speaker": "B", "start_ms": 4000, "case": "rapid_turn"},
  {"audio": "a-02.wav", "speaker": "A", "start_ms": 1800000, "case": "returning"}

```

```powershell
py -3.10 tools/meeting_speaker_bench.py D:\bench\meeting.json --backend campplus --out D:\bench\campplus.json
py -3.10 tools/meeting_speaker_bench.py D:\bench\meeting.json --backend mel --out D:\bench\mel.json
```

路径相对清单；`route` 可选 `mic` / `system`，未知时留空。显式选择 CAM++ 而加载失败会报错，
避免把回退结果写成 CAM++。输出包含实际后端、逐段判断、场景分组、拆人/并人/待确认率、覆盖率
和嵌入加匹配的实时率。音频须预先标成单人发言；本工具不测一段内的换人边界，也不输出 DER。
声音重叠、未切开的多人片段另做时间对齐标注评测，不混入这份单人片段表。
