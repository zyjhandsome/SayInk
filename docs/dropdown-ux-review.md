# 下拉选择与关联控件 UX/UI 审查

审查日期：2026-10-19。对象：当前工作区源码及用户提供的暗色截图。

整体判断：页面已有清楚的卡片分组、颜色层级和统一的单行输入高度。下拉控件的问题主要集中在箭头与主体绘制不协调、状态表达不完整、宽度规则分散，以及跨页面的语义与菜单样式差异。应先处理会导致误操作、看不出是否可用的问题，再整理外观细节。

本次只新增评审文档与隔离审查产物，没有修改产品实现，也没有覆盖工作区已有修改。

**范围与证据边界**

- 逐项定位 16 处下拉选择框；原生离屏渲染覆盖全部 16 处的深浅两种主题、收起态与展开态。
- 补充检查 2 处数值步进框、5 个页面操作菜单，以及托盘主菜单和模型子菜单。
- 额外模拟正常、悬停、焦点、禁用、选择确认、Esc 取消、滚轮经过、60 字符长选项。
- 预览使用虚构会议、临时配置和模拟模型／设备列表，不读取个人历史、不采集音频、不联网。设备截图主要用于验证控件呈现，真实设备枚举与热插拔行为没有端到端实测。
- 本轮全页面预览为 100% 缩放；虚拟屏幕可用区域为 800×800 逻辑像素。长选项越界结论限定在这一条件。真实显示器、多屏和 150%／200% 缩放仍需验收。
- 代码图谱可以定位文件，但部分符号位置与工作区最新内容不一致，故具体结论以当前文件和原生渲染为准。此前页面一致性报告中的通过项没有直接当成本轮结论。

**收起态的具体评价**

基础高度 40 与单行输入框一致，中文字号、输入底色和 8 像素圆角也已有共用基础。截图中右侧控制列与开关右边界基本整齐，这些都应保留。

最突出的问题是右侧箭头区域：主体使用现代、扁平的输入框样式，箭头却保留了 Fusion 的局部立体边缘。浅色主题下右边的灰色折角尤其明显。修整的重点应是完整外轮廓和状态连续性，而不是简单改箭头颜色。

不同字段的宽度没有必要全部相同。120 宽的数值框有单位与短数值，320 宽的设备框需要容纳设备名，差异本身合理。真正影响协调性的是同一小组内缺少共同列宽，以及没有清楚的宽度档位与窄窗口退让规则。

框内值应优先表达当前选择。下载源中的长策略说明、继承项中的实际设备信息可以移到辅助说明，减少值区文字拥挤；移动后仍应就近显示实际生效结果，避免把有用信息全部隐藏。

**展开态的具体评价**

列表的表面色、文字色和圆角已与页面主题一致，弹层不以选中项覆盖原框展开，代码也在打开前计算内容宽度。这些是有价值的基础。

目前选项行实际约 44 像素高。模型列表 10 个选项的弹层约 454 像素高，相比同页紧凑的操作菜单偏宽松。应统一“最终外部行高”的定义，避免声明的最小高度再叠加内边距后超出预期。桌面选择列表可以评估 36–40 的行高；需要大目标时再采用更宽松规格。

选中、悬停、键盘活动项需要能同时表达不同含义。当前蓝色强调会随候选项移动，不应把这直接解读为值已经保存。固定的已选标记能减少这一推断成本。

模型和模板列表还需要内容层级。模型可以在每项末尾提供已下载／未下载信息；模板可以区分内置和自定义，并在选择后就地显示简短用途说明。当前规模不必立即添加搜索框；当用户模板或设备数量持续增长时，再考虑搜索与过滤。

弹层通常至少与框等宽，必要时可以更宽；不要求强行等宽。但增宽必须受屏幕可用区域约束，并保留稳定的锚点、右缘避让和合适的最大高度。当前 60 字符探针说明仅移动弹层位置不足以解决超宽。

**页面协调性与交互语义**

通用设置的“左侧标签与说明、右侧控件”适合偏好设置，AI 服务的“上方标签、下方整行字段”适合较长内容，会议详情的紧凑工具行也有明确任务依据。这几种布局可以并存，统一重点是组件本身和语义，不需要把全部页面改成同一种表单。

主题只有三个高频、短标签选项，保留分段选择有助于一眼看出当前主题。数值保留规则继续使用可直接输入的步进框，也比把大量数字塞进下拉列表更适合。两者需要与下拉框共用边框、焦点与禁用规范。

会议默认设置、开始卡片、本场临时选择之间已有说明，但用词未完全一致。建议统一用“跟随听写设置”，再显示“当前：麦克风／Fun-ASR-Nano”等实际结果；开始卡片明确“仅本场”，设置页明确“用于之后新会议”。不要只显示一个模型名，让用户猜它是继承还是固定选择。

操作菜单与选择菜单应有共同的颜色、圆角、文字和反馈原则，同时保留任务差异：选择菜单帮助确认一个值，操作菜单执行命令。“更多”与“发言人”的菜单箭头被隐藏，而“导出”保留默认指示，打开方式提示也应形成一致约定。“更多”可用省略图形表达；“导出／发言人”更适合明确的下拉指示。

**建议建立的共用规范**

| 项目 | 建议规则 |
| --- | --- |
| 字段外部高度 | 普通单行字段保持 40；焦点、悬停和禁用前后尺寸不跳动。 |
| 圆角 | 字段保持 8，弹层与页面圆角体系协调；四个外角包括箭头区都连续。 |
| 控件宽度 | 同组标准选择框可先以 256 为候选值验证；设备／长值以 320 为候选上限，短值单独设档；弹性工具行按剩余空间布局。最终值结合最长文案与窄窗口验证。 |
| 内边距与箭头 | 文字左侧约 12；箭头区域约 28–32；箭头图形统一为约 10–12，居中对齐并随状态换色。整框可打开。 |
| 选项行 | 普通桌面列表评估 36–40 的最终行高；固定预留已选标记列；说明文字有独立层级。 |
| 状态 | 正常、悬停、键盘焦点、展开、禁用、不可用原因均有明确规则；展开态与原框保持关联。 |
| 长值 | 收起态明确省略；名称完整提示；展开态设置屏幕宽高上限，必要时换行。设备提示和模板说明不能互相替代。 |
| 键盘 | Tab 可到达、方向键浏览、Enter 确认、Esc 关闭；对当前值与候选值的反馈保持一致。 |
| 滚轮 | 收起的选择框不因滚动页面改变值；数值框采用同样防误改原则；展开列表内部正常滚动。 |
| 生效反馈 | 就地解释继承、默认、本场临时、尚未生效、模型未下载；不为每次普通选择增加额外弹窗。 |
| 跨页面使用 | 页面和弹窗共用同一个基础选择组件与菜单样式；允许显式的紧凑／弹性布局变体。 |

图形实现需要结合 Qt 的绘制限制验证。项目已有关于“只重写箭头子控件会导致箭头消失”的回归说明，不能只隐藏原箭头区而不提供完整替代。建议在共用层完整处理，而非逐个页面叠加局部样式。

**修复后的验收顺序**

1. 滚动页面经过数值框不修改配置；直接输入和步进按钮仍正确工作。
2. 正常、悬停、禁用状态清楚可辨；实际禁用的电脑播放设备与生成中的模板都有解释。
3. 深浅主题下箭头与主体的边框、圆角连续；焦点框完整且尺寸不变。
4. 已选第一项、悬停第二项时，两种状态同时可识别；Enter 确认、Esc 取消与实际值一致。
5. 会议导出、更多、发言人、历史、托盘的菜单基础样式一致，禁用项与删除类操作清晰。
6. 三个会议开始字段保留可见标签；窄窗口不会只剩难以辨认的当前值。
7. 长设备名、60 字符模板名、小屏、高缩放、多屏边缘条件下可读、可选、不会越界。
8. 设置页与会议页的模板说明随当前项同步，继承值的命名和生效范围一致。
