# 识别优化第七轮（2026-10-21）：术语误写替换与 LLM 纠错

第六轮把说话人这条线的待办收口后，剩下的是文字识别准确率的「建议 7」：ASR 二遍解码或
LLM 纠错。本轮先量了两条路各能拿到多少，然后只做了量得出收益、风险可控的那部分。
与前几轮一样，所有数字来自 AISHELL-4 `M_R003S04C01` 第 0 通道前 10 分钟（远场阵列
单通道、6 人、8.9% 重叠、参考 2812 字），CER 口径见 [`asr-benchmark.md`](asr-benchmark.md)。

## 结论先行

| 路线 | 结论 | 原因 |
|---|---|---|
| 二遍声学解码（置信度低的片段换模型 / 换参数再解一次） | **不做** | sherpa-onnx 1.13.8 里 Fun-ASR-Nano 与 FireRedASR2-CTC 的 `OfflineRecognitionResult.ys_log_probs` 为空，没有可用的声学置信度；两款模型 RTF 0.26–0.39，二遍解码会把实时率推过 0.3 的目标；应用不保留音频，事后也没有「再解一次」的材料 |
| 术语误写直接替换（`词=误写1、误写2`） | **做了** | 零延迟、零费用、行为可预期；`stt.glossary` 的 `variants` 字段此前只存不用 |
| LLM 纠错模式（润色的严格版） | **做了，作为可选处理方式** | 真实纠正存在（增→赠、训盘→新盘、五中→五证），但整体 CER 变化在 ±0.3 个百分点内；必须配更严的接受门槛，否则模型会顺手删口语词 |

## 量出来的数字

### LLM 纠错（DeepSeek `deepseek-flash`，关闭思考，温度 0）

仓库外脚本先在同一段音频的 48 个 Silero 片段上试了四种喂法（有无上文、有无术语表）：

| 模型 | 原始 CER | 纠错后（上文） | 纠错后（术语表） | 中位延迟 | 10 分钟 token |
|---|---|---|---|---|---|
| funasr-nano | 30.97% | 30.83% | 30.90% | 0.84 s | ≈14k |
| fireredasr2-ctc | 34.14% | 33.96% | 33.89% | 0.84 s | ≈14k |

- 看得见的真实修正：增送→赠送 ×6、训盘→新盘、五中→五证。
- 看得见的副作用：删口吃和「嗯 / 那个」、补标点、合并短句——这些是润色，不是纠错，
  会让「原文保真」失守；接受门槛（下文）就是为它设的。
- 数字门槛也拦下了一个本该接受的修正（五四证→五证，被当成「数字被改动」）。本轮把术语
  替换提到纠错之前并让门槛以「替换后的原文」为基准，这个修正现在直接由替换完成。
- 参考文本不含口语词、S/D/I = 9.7% / 19.8% / 1.5%，删除错误占主导：这段音频上 CER 基本
  由漏字决定，文字纠错**量不出**整体收益，收益只体现在术语写法上。
- `deepseek-flash` 默认思考：推理 token 会吃掉 `max_tokens`，返回空 `content`；加
  `thinking: {"type": "disabled"}` 后延迟从 2.85 s 降到 0.84 s。应用只对
  `api.deepseek.com` 的 `deepseek-flash` / `deepseek-v4-pro` 加这个字段。

### 仓库内复现（`tools/asr_bench.py --llm-correct`）

同一段音频，`glossary.txt` 为 `赠送=增送 / 新盘=训盘 / 五证=五中、五四证`，`--speaker-turns off`：

| 模型 | CER（热词 + 误写替换） | LLM 纠错后 | 热词命中率 | 改动段 / 拒绝 | 中位延迟 |
|---|---|---|---|---|---|
| funasr-nano | 31.86% | 31.79% | 60.0%（6 / 10） | 4 / 2（数字被改动） | 0.75 s |
| fireredasr2-ctc | 34.17% | 34.00% | 30.0%（3 / 10） | 8 / 3（数字被改动） | 0.90 s |

两点要单独说明：

1. **funasr-nano 带 3 个热词后 CER 从 30.97% 升到 31.86%**。对比逐段文本，热词改变的
   是整段解码（多出「呃」、断句与标点变化，231 处差异），不只是术语本身；五证命中从
   4 / 9 升到 6 / 9，但参考稿不含口语词，多出来的「呃」全算错。热词不是免费的，列表要短、
   只放真正常错的词；这一点写进了 README。
2. 误写替换对 fireredasr2-ctc 只改了 1 处（五四证→五证），对 funasr-nano 一处未命中：
   带热词后它把「新盘」写成了「信盘」而不是「训盘」，最后由 LLM 改对。误写表只能覆盖
   用户已经见过的写法，这是它的边界。

## 实现范围

- `sayink/asr_correction.py`（新，纯 Python，不依赖 Qt）：
  - `parse_glossary_line` / `format_glossary_line`：`词=误写1、误写2`（`=` 或 `＝`；分隔符
    `,` `，` `、` `;` `；`），每条最多 5 个误写、每个不超过 20 字，误写等于本词时丢弃。
  - `apply_glossary_variants`：最长优先、一次扫描、不回扫；英文整词、不分大小写；误写与
    另一条术语同名时跳过。
  - `CORRECTION_PROMPT` / `correction_user_prompt`：术语表写成「正确写法 ← 误写」，上文只取
    最近一句输出的末尾 120 字并标明「仅供参考，不要输出」。
  - `correction_rejection_reason`：先过润色的保真检查（数字、否定、英文专名），再要求
    压缩后长度在 0.85–1.15 倍（+4 字）以内、编辑距离 ≤ max(2, 20%)；基准是「已做误写替换
    的原文」。
- `sayink/polish_fidelity.py`（新）：润色保真检查从 `app.py` 搬出来，供纠错与评测复用；
  `app.py` 继续导出同名函数。顺带修了一个旧问题：名字前面紧挨数字时（`2024Q3`、`0GitHub`）
  原文不变也会被判「英文专名丢失」而回退原文。
- `sayink/text_polisher.py`：`LLM_MODE_CORRECT`、`normalize_llm_mode`、`thinking_payload_extra`
  （`llm_transport` 同步改用）；`PolishWorker` 在纠错模式用温度 0、附带术语表与上文；
  内置提示词原样粘回编辑器不算自定义，切换处理方式仍切换提示词。
- `sayink/config.py`：`llm.mode` 只返回 `polish` / `correct`，其他值回落 `polish`。
- `sayink/app.py`：每个最终结果在大小写还原后做误写替换；润色 / 纠错按 `llm.mode` 路由，
  记住本句的模式与术语表，回包用对应门槛；记录最近一次输出及时间（2 分钟内才作上文）。
  会议逐句处理仍由 `meeting.polish_segments` 决定。
- 设置：AI 服务 → 文字润色新增「处理方式」下拉（润色 / 纠错）；通用 → 自定义词汇的占位与
  提示说明等号写法，保存与回填保留误写。
- `tools/asr_bench.py`：`glossary.txt` 支持等号写法并在识别后做同样的替换；`--llm-correct`
  （`--llm-url`、`--llm-model`，密钥取环境变量 `SAYINK_LLM_API_KEY`）多输出一列纠错后 CER
  与每个文件的改动 / 拒绝 / 延迟。
- 测试：`tests/test_asr_correction.py`（39 项）覆盖解析、替换、提示、门槛、模式路由、配置、
  应用接线；设置页新增词汇往返与模式往返测试；`test_polish_fidelity.py` 新增数字前名字的用例。

## 没有做的

- 二遍声学解码：原因见结论表。若未来 sherpa-onnx 暴露逐 token 概率，可按「低置信片段才
  重解」的口径在 `asr_bench.py` 上重新量。
- 会议文字稿的事后整段纠错：会后已有「原文精整」模板走纪要模型，不再加一条相近的路。
- 自动从历史里学习误写：需要用户确认的编辑才能当训练信号，当前历史编辑不记录对应关系。
