# 说话人与语音识别准确性分析（2026-10-20）

结论：仍有明确的提升空间。当前实现已具备 CAM++ 声纹、多样本档案、谨慎匹配、
人工纠正学习和片段内换人分析，但短插话、重叠发言、输入来源变化仍存在结构性限制。
继续调一个相似度阈值不足以同时减少拆人和并人。建议先保护声音档案、保留输入轨道，
再加强帧级换人与文字时间对齐，最后以人工标注评测决定模型与参数。

本文是当前工作区代码审查和真实录音诊断，未修改业务识别策略。
下述实验实际调用本机 CAM++、Fun-ASR-Nano 和 FireRedASR2 CTC，未使用合成语音。
拼接、叠加和频段处理是对真人录音的受控变换，不能当成自然会议测试集。

## 同一个人、不同时间和不同输入

| 实际诊断 | 本次结果 | 可以说明什么 |
|---|---|---|
| A 建档后，将 A2 的传入时间设为第 30 分钟 | 相似度 0.7421，编号仍为 1 | 此片段在较长时间间隔后能够回到原声组；并非实际录制了 30 分钟会议 |
| 同一个 A，音量变为 0.25 倍 | 相似度约 1.0，编号仍为 1 | 本次较温和音量变化未造成拆人 |
| 同一个 A，音量变为 0.10 倍 | 返回零特征，编号为 0 待确认 | 绝对音量门限会让仍有可辨文字的输入失去说话人归属 |
| 同一个 A，保留 300–3400 Hz 频段 | 相似度 0.6395，编号仍为 1 | 模拟频段变化降低了声纹相似度；不等同真实电话或蓝牙设备评测 |
| 同一个 A，叠加延迟 100 ms、幅度 0.4 的自身回声 | 相似度 0.9270，编号仍为 1 | 此单一模拟回声条件下未拆人；不代表已实现回声消除 |
| 完全相同的 A，先标记为 mic，再标记为 system | 现场编号 1 → 2 | 来源被当作候选人硬过滤，可能主动拆开同一个人的声音 |

来源硬过滤位于 `sayink/meeting_speakers.py:146` 的 `_choose()`。
即使两段嵌入完全一致，不同的非空 route 也不会互相比较。
会议结束后的重聚类可能再次合并两个未锁定声组；本次的 1 → 2 指现场匹配结果，
不能据此断言最终导出也必然拆成两人。

建议将“人物身份”和“采集来源”分开建模。保留每个来源的可靠样本，
把来源作为辅助证据；同人跨来源合并需多段一致证据或人工确认，不能一律直接合并。
先处理串音与回声，避免把同一段扬声器声音在两条轨道中重复计为两次发言。

对于时间变化，当前每人最多保留 12 条代表声音，保留最初锚点，能够覆盖一定音色变化。
但未见按信噪比和说话状态标定的置信分数，匹配主要使用与已有样本的最大余弦相似度。
单条混入错误人物的样本就可能影响以后匹配，不能简单增加样本数量或放宽阈值。

跨会议是另一项能力：`MeetingController.finalize()` 会释放本场声音档案，
下一场不继承声纹。因此“下次开会仍认出同一个人”目前没有实现。
如果需要，应单独设计用户主动启用、可确认与可删除的个人声音档案，
不能把本次会议编号直接当成持久人物身份。

## 快速接话、短插话和重叠

当前 `sayink/speaker_turns.py` 使用 1.2 秒窗、0.4 秒步长。
候选切点左右还需要至少各 1.6 秒语音支持换人，最长验证上下文各 3 秒。
这有助于减少同一人因笑声、字音和语气变化被误拆，但对很短的插话不利。

以下测试直接拼接真人片段，拼接点精确已知，未改变片段内部语速或音高：

| 受控输入 | 拼接点 | 当前检测结果 |
|---|---|---|
| A 4 秒 → B 4 秒 → A2 4 秒 | 4.00、8.00 秒 | 未切开，整段待确认，不更新档案 |
| A 4 秒 → B 0.8 秒 → A2 4 秒 | 4.00、4.80 秒 | 仅在 5.64 秒切开，两段均被标记可学习 |
| A 4 秒 → A2 4 秒 | 同来源连续发言对照 | 未切开 |

按已有边界评测工具的 500 ms 容差，第二个受控例子的两个拼接点都未命中，
且多出一个切点。人工拼接的声学突变和截断字音也会影响模型，
不能将这三个例子外推为自然接话的准确率。

更值得优先解决的是重叠声音被当成可靠单人样本。
把 A、B 各取 4 秒，构造 `0.5*A + 0.5*secondary_gain*B`：

| B 相对 A 的幅度 | 质量门是否通过 | 换人检测 | 先用 A 建档后的编号 | 是否允许学习 |
|---:|---|---|---:|---|
| 0.25 | 是 | 无切点 | 1 | 是 |
| 0.50 | 是 | 无切点 | 2 | 是 |
| 1.00 | 是 | 无切点 | 2 | 是 |

这里的 2 是混音被分配的一个声组编号，不能解释成成功找出了第二位发言人。
在更响的两个混音条件下，系统把混合声纹作为新组建立；较弱干扰也可能写入原组。
这些结果直接对应 `voice_sample_is_clear()` 只检查有效数据、响度、时长和削波，
并不检查是否只有一个人在说话。换人检测也不是重叠检测。

建议优先接入帧级重叠检测，重叠区间不建立或更新单人档案，并保留明确的重叠状态。
检测不确定的区间也应单独传递状态，不能仅凭有非零向量就认定为可靠单人声音。
在具备证据之前，不能依靠“同一人连续说话”规则吞掉短促回应。

麦克风与电脑声音的分轨采集结果在 `AudioRecorder._drain_mixed_mono()` 中汇成单声道，
后续无法利用完整的原始来源轨道。建议保留同步的两条处理轨，分别做 VAD、质量判断和 ASR，
再以统一时钟合并时间线；来源不等于人物，一条电脑音轨仍可能有多位远端参会者。

对于同一轨道中真实同时说话，先可靠标记重叠，再评估仅对重叠区间运行声音分离与多流 ASR。
重叠检测只能回答“多人同时说话”，不能自动恢复每个人说的文字。
分离输出还需要检查伪影、漏词和串人，不能直接作为可靠建档音频。

## 文字识别与人物归属应分别衡量

`decode_asr_slice()` 当前只返回规范化后的 `stream.result.text`，不向后续流程传递
token 时间、置信信息或多候选结果。短句重试仅在首次识别为空时触发，
已有文字里的同音字、姓名、数字或专业术语错误不会因此得到纠正。

本次使用 A 的同一段 5 秒真人录音，比较输入改变前后同一个模型的输出：

| 输入 | Fun-ASR-Nano | FireRedASR2 CTC |
|---|---|---|
| 原始 | 非空 | 非空 |
| 音量 0.25 倍 | 与自身原始输出一致 | 与自身原始输出一致 |
| 音量 0.10 倍 | 与自身原始输出一致 | 与自身原始输出有差异 |
| 300–3400 Hz 频段 | 与自身原始输出有差异 | 与自身原始输出有差异 |

这里检查的是输出稳定性，原始模型输出也可能有错。
结果文件中的相对编辑距离以同一个模型的原始输出为参照，**不是人工金标 CER**，
不能用来给两个模型排名。两者在 0.10 倍音量下仍能返回文字，而声纹已拒绝归属，
说明 ASR 可用不代表人物归属可靠。

本次原生结果中 Nano 的 `tokens/timestamps` 字段长度均为 21，CTC 均为 22。
只检查了字段存在与长度，没有核验时间值是否有效、是否逐字准确以及是否与文本一致。
应先核验并保留可用的原生时间信息；若不足，再评估独立强制对齐。
不能把非空的 timestamps 字段直接当成准确的字级时间戳。

建议保留较完整语音上下文进行文字识别，再结合有效词级/字级时间戳分配说话人。
对于必须分段的路径，评估边界上下文补偿与基于时间戳的去重，
防止直接切在词中间造成漏字、重复和归错人。
对姓名、数字、英文缩写与专业词做有音频依据的局部二次识别，保留原文和改动证据。
文字润色不能恢复被覆盖的第二路声音，也不应凭语义推断负责人。

本次 Nano 5 秒短片段解码 RTF 为 0.795–1.039，CTC 为 0.528–0.599，
不包含加载与声纹分析。仅为一次短片段诊断，硬件负载未隔离，不能外推为长会议性能或选型依据。
已有 108 秒回放也观察到耗时波动；应单独测处理耗时、从发言到显示的延迟和队列积压。

## 可评估的实现路径

| 优先级 | 工作 | 目标与约束 |
|---|---|---|
| P0 | 重叠/不可靠片段禁止训练单人档案；保留明确状态 | 先阻断混音污染，必须同时观察待确认率与覆盖率 |
| P0 | 分轨保留、时钟同步、回声/串音处理；调整来源硬过滤 | 减少换输入拆人和重复发言，不把来源直接当成人物 |
| P1 | 帧级说话人活动和短插话检测 | 使用较长语音建立身份、较细时间粒度定位变化，减少窗口折中带来的漏检 |
| P1 | 原生时间信息核验、上下文 ASR、词/字级人物归属 | 减少切词、丢短回应和边界处文字归错人 |
| P1 | 可回溯的会后重分配 | 当前会后逻辑主要合并声组，无法拆开一个组内已并错的多人；需要带时间位置的片段证据 |
| P2 | 重叠区间局部分离、多流 ASR | 在分轨和重叠检测之后评估，对分离伪影与漏词单独计分 |
| P2 | 跨会议人物档案 | 与匿名声组分开设计，需明确的使用场景和用户控制 |

会后 `recluster()` 对声组中心建立合并关系，再以旧编号映射新编号。
它没有重新切开已混合的片段，也不能把一个旧编号里的不同真人分开。
还应检查相似度传递造成的链式合并，加入时间重叠互斥、人工确认保护等约束。
这部分是代码审查推断，本次未进行其独立准确率评测。

与现有 Windows/CPU/ONNX 栈较接近的候选，是 sherpa-onnx 官方已提供的
[pyannote segmentation 3.0 ONNX 分段模型](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/models.html)，
再结合现有 CAM++。上游 [segmentation-3.0 模型卡](https://huggingface.co/pyannote/segmentation-3.0)
说明其局部帧分类包含双人重叠状态，单个 10 秒窗口最多三位局部说话人、每帧最多两人。
需要验证所采用 ONNX 接口是否保留这些状态，不能假设现成聚类输出会自动提供完整重叠信息。
本次没有下载或实测该新模型。

[pyannote Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1)
可作为离线参考方案，其模型卡区分普通与 exclusive 说话人时间线。
exclusive 结果便于文本对齐，但不能代替保留真实重叠情况的时间线。
它是另一条运行栈，需要另外评估 Windows 打包、CPU 耗时和模型获取条件。

如原生时间戳无法满足需求，可对照
[Qwen3-ForcedAligner 官方说明](https://github.com/QwenLM/Qwen3-ASR#forcedaligner-usage)，
评估中文词/字级对齐；它有额外模型与算力成本，不直接改变当前默认引擎。

以上是根据现有代码与官方能力说明提出的候选方案，不是已经验证优于当前实现的结论。

## 怎样证明改进有效

正式评测应同时包含自然会议、访谈/圆桌节目和受控真人录音诊断，三者分别报告。
至少覆盖 30 分钟、多场会议、不同性别和相似音色、不同输入来源，
以及 A→B→A、0.2–1 秒插话、同人久后返回、远场、回声、噪声与重叠区间。
同一真人不同日期的录音应进入独立测试集；开发标定数据与最终验收数据按人物/场次隔离。

| 指标 | 为什么必须同时看 |
|---|---|
| CER/WER，姓名/数字/术语错误 | 衡量文字，不用声组数量代替 |
| DER：漏检、误检、人物混淆分别统计 | 对时间和人物一起计分，声明是否计入重叠与边界容差 |
| 按人物归属计的 cpCER/cpWER 或相应归属错误率 | 防止文字正确但全归给错误人物 |
| 拆人率、并人率 | 对应同一个人被拆开、不同人被合并 |
| 待确认率、覆盖率及已归属片段错误率 | 防止通过大量拒绝归属得到表面改进 |
| 短插话召回、误切率、边界误差 | 暴露整体平均值掩盖的快速接话问题 |
| 重叠检测精确率/召回率、重叠区间多流文字错误 | 区分发现重叠与恢复各人发言 |
| RTF、尾延迟、积压、内存 | 确认长期运行不会因新增分析持续落后 |

可以使用有人工转写与人物活动标注的真实会议集补足节目字幕的不足：
[AliMeeting](https://www.openslr.org/119/) 提供真实中文会议、近远场和多人重叠；
[AISHELL-4](https://www.openslr.org/111/) 包含真实 4–8 人会议、快速接话与重叠标注。
本次仅核查官方说明，未下载其数 GB 的测试包，也未以它们宣称评测结果。

第一阶段验收应要求：在固定测试集和可比较覆盖率下，人物混淆和混音污染减少；
单人稳定样本不增加误切；文字错误率不因换人切分变差；处理余量满足项目目标。
具体百分比应在取得第一批人工金标基线后确定。
