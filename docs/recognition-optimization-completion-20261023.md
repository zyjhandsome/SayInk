# 连续讲话完整性与识别优化验收（2026-10-23）

本轮清单覆盖单次转写、持续转写和会议。实现与评估均已完成；有稳定依据的保护进入默认流程，
会改变存储行为、增加计算或尚未证明稳定收益的能力保留独立开关，默认关闭。
第一轮记录见 [连续讲话第一轮](recognition-continuity-20261023.md)。

## 清单与最终行为

| 项目 | 最终实现与结论 |
|---|---|
| 强制分段短尾音 | 保留紧接切点的短续音，真实停顿后取消保护；不改变原始切点；App 不再二次过滤短于 100 ms 的合法续音 |
| 真实重复与混合语言 | 清洗仅移除已知引擎标记，保留真实重复及多语言；术语、大小写修改前的原文单独保存 |
| 异常循环 | 超出宽松语速预算且短语循环至少 8 次时，用全部原音频作一次有界分片复核；失败保留首次文字 |
| 流水线与取消 | 只预识别队首一段，输出和历史仍串行；取消后的旧原生调用退出前，新任务不进入同一解码器；去掉段后 300 ms 固定等待 |
| 跨段音频上下文 | 已实现原采样范围之外各最多 300 ms 的上下文。只接受有效词元时间戳、顺序、范围及完整文本覆盖，按原时间范围归属；十进制点、负号等也必须覆盖。没有时间戳、校验失败、空结果时识别原片段。**两份 CTC 样本均退步，实验开关默认关闭**；默认 Fun-ASR-Nano 不启用此能力 |
| 轻声 | 常规 ASR 对明显起伏的低音量片段做有界归一化，不增加模型调用。另提供「轻声增强（安静环境）」：实际加载 Silero 后，VAD 输入最多增强 4 倍并降低有声底线，ASR 输入最多增强 32 倍且限制峰值；原始录音和声纹输入不变。数字静音拒绝，能量回退不启用强增强；默认关闭，噪声环境可能误触发 |
| 麦克风 / 系统声音 | 「混合音源分别识别」独立 VAD、音源标签和采样时间；等待更早的未结束发言后按采集时间送出，收尾送完两路。仅分开已经独立采集的两路，不能拆开同一音轨里的混合人声；默认关闭，可能增加延迟和总计算量 |
| 录音恢复 | 明确开启后，从下次录音起在本机缓存 VAD 前的声音；混合采集保留回声扣除、配平前的原始两路。写入队列最多 20 块，原声文件为可恢复的 float32 流，约每秒同步；完整采样可在进程异常退出后恢复。恢复窗支持音轨选择、WAV 导出、本机重新识别、另存文字和单独删除；不自动粘贴或调用远程服务 |
| 长时排队 | 仅缓存健康的主动开启会话允许磁盘排队，约 2 分钟以后的片段落盘；保留场次、顺序、采样数及上下文。消费后移除临时片段。磁盘失败时保留内存并使用原有 3 分钟保护；坏文件保留证据、暂停采集并提示原声恢复，后续片段继续处理 |
| 驱动与设备故障 | 设备断开先送出已录尾音，空录音只报告设备错误；输入溢出明确提示可能存在缺口，继续接收后续音频，不能补回驱动没有交付的采样 |
| 界面与退出 | 新开关使用独立配置流程，不清空已有队列；轻声、跨段选项沿用识别设置的延后生效规则。恢复期间独占驻留解码器，禁止新录音 / 会议，退出等待工作线程与缓存写入收尾。修复关于页展开后整列上移的问题，补齐键盘 Tab 顺序 |

## 存储与隐私边界

默认不保存音频；转写历史开关与录音恢复开关互相独立。声音测试不会因为开启录音恢复而保存音频。
会议开始卡、通用页、README 均已说明例外，声纹始终不落盘。

录音缓存上限 2 GB；每场待识别临时片段另占最多 2 GB，保存于所属录音目录。可用磁盘低于约 128 MB
或后台写入跟不上时明确报错，停止缓存；原有队列继续处理。正常结束的缓存在下一次启用缓存时清理
超过 7 天的内容；异常中断缓存不自动删。删除文字历史或会议不会删除录音，需在恢复窗单独管理。

进程异常退出能恢复已写入的完整采样；最后仍在队列中或未完成同步的声音不保证保留，断电和驱动
丢帧不可能靠这套缓存承诺零丢失。缓存健康也不能无限录音，仍受磁盘容量和设备限制。

## 真人对照

使用本机已有的 AISHELL-4 `M_R003S04C01`、`S_R004S03C01` 第 0 通道前 600 秒，
分别涉及 6 / 5 个标注说话人；独立原始录音共 20 分钟。参考来自相同 TextGrid，统一沿用仓库 CER
口径，基线为 `1cca10dfb62d60956dda801d94ec7c9b710c5bf9`。使用实际 int8 模型、CPU 4 线程、
中文、无热词、无 LLM、关闭换人分析。文件哈希、全部数值见 [评测数据](recognition-optimization-results-20261023.json)。

### 普通音量 CER

| 模型 / 录音 | 基线 | 默认优化 | 打开实验性跨段上下文 |
|---|---:|---:|---:|
| Fun-ASR-Nano / M | 30.97% | 30.55% | 不支持词元时间戳，不启用 |
| Fun-ASR-Nano / S | 10.17% | 10.17% | 同上 |
| FireRedASR2 CTC / M | 34.14% | 34.14% | 34.53% |
| FireRedASR2 CTC / S | 9.88% | 9.88% | 10.38% |

原始 VAD 切片仍是 48 / 52 段，送出时长为 568.3 / 561.9 秒。普通音量默认路径没有精度回退，
也没有因一般重复而增加二遍解码。跨段上下文虽通过时间戳校验，仍会改变模型的解码选择，不能据此
假设整体精度必然提升；本轮不默认启用，不为不提供时间戳的模型使用文字猜测去重。

### 低音量压力测试

把同两份录音各自前 180 秒整体乘以 0.05（约降低 26 dB），保留原噪声与语音比例，参考不变。
这是由真人录音生成的数值压力测试，不是新设备、真实耳语或新录音数据。

| 模型 / 录音 | 基线 CER | 开启轻声增强后的 CER |
|---|---:|---:|
| Fun-ASR-Nano / M | 97.31% | 45.38% |
| Fun-ASR-Nano / S | 98.71% | 64.72% |
| FireRedASR2 CTC / M | 97.82% | 52.05% |
| FireRedASR2 CTC / S | 98.87% | 62.14% |

两份低音量样本送出的音频从 7.2 / 2.3 秒增加到 122.1 / 70.7 秒，说明主要收益是减少检测环节的
整句遗漏；仍存在明显错漏。强增强与较保守增益的比较并非每个样本都更好，因此该能力默认关闭，
不推广成通用噪声消除，也不据此改动普通音量的 VAD 默认值。

### 两路同时发言

从两个会议各取无其他说话人标注重叠的清晰发言，分别作为麦克风 / 系统声，控制音量后同时混合。
这是两个受控混音案例，不是物理设备的双轨实录。单路混音的 CER 取两种参考先后顺序中较好的一种，
双轨 CER 按各自人工参考的字符数加权，尽量不把重叠时的文字排列差异当作识别损失。

| 案例 | 混合后识别 CER | 分别识别 CER |
|---|---:|---:|
| 6.27 秒同时讲话 | 67.31% | 13.46% |
| 7.40 秒同时讲话 | 45.65% | 15.22% |

两次分别识别的总实时率约为 0.34 / 0.28，混音识别约为 0.26 / 0.19。分别识别确实增加了计算，
但这两个短案例在本机仍可实时处理。结果不代表任意通话、同轨多人重叠、强回声或真实设备时钟偏差。

本轮部分模型评测并发执行，耗时仅用于判断数量级，不能把不同次运行的小幅差值解释为模型推理提速。
普通音量模型解码实时率约在 0.20–0.35；无条件保证“更准且任何场景都不增加延迟”不符合这些结果。

## 可复现验证

```powershell
py -3.10 tools/continuity_eval.py --data <本地AISHELL4目录> --out <对照.json>
py -3.10 tools/continuity_eval.py --data <本地AISHELL4目录> --only-quiet-enhancement --out <轻声.json>
py -3.10 tools/lane_asr_eval.py --data <本地AISHELL4目录> --out <双轨.json>
```

工具只读取指定本地样本和已有模型，不访问网络、用户凭据或正式历史；仅写入指定 JSON。
这批数据只覆盖两场录音，尚不能代表所有口音、设备、词汇和噪声。44.1 / 48 kHz 重采样、输入偏斜、
设备错误和三种模式生命周期由回归测试验证；这与跨设备真人识别评测是不同证据。

自动化包含三种模式下 15 秒临界点、30 分钟及 2 小时连续输入的采样覆盖；双轨重叠、时间排序与
短尾收尾；25 分钟积压的内存边界与磁盘顺序；真实子进程异常退出后的原声恢复；损坏元数据、
半个采样、磁盘配额、输出失败、取消和迟到结果；恢复窗口与新控件的键盘操作。合成采样连续性
不等于真人讲话逐字无误。

验证环境为 Windows、Python 3.10.11、PyQt6 6.11.0、sherpa-onnx 1.13.8。
完整回归 **2424 项通过**，352.00 秒；Windows 单实例命名管道需要在沙箱外运行，用户配置与凭据均由
测试夹具隔离。过程中发现的设备断开空完成事件、历史隐私说明及新增控件 Tab 顺序三处接缝已修复。
最后审查补上“录音中重建断句器先送出等待上下文的片段，再重置各路采样时钟”的保护，随后
**125 项相关定向测试通过**，13.77 秒；包含新边界用例，与完整回归有重叠，不相加。
`ruff check`、`git diff --check`、发布依赖核对及 `pip check` 均通过。完整回归也覆盖并通过了原有的
关于页展开滚动位置用例。
浅色 / 深色新设置与恢复窗口已渲染核对；offscreen 平台未枚举系统字体时，预览显式载入系统 YaHei / Segoe 字体。
