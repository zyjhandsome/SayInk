# 长会议整理与流式生成

会议纪要和原文精整使用可取消的 HTTPX 异步请求，在工作线程中运行；日常短句润色保持原有流程。

## 输入、输出与合并

- 会议入口和生成器统一采用 8000 字符的分段上限，已有 `meeting.single_request_char_limit` 配置可以进一步降低上限。超长单句也会拆分，每段保留原说话人和真实时间戳。
- `meeting.context_window_tokens` 默认 32768，`meeting.max_output_tokens` 默认 4096。这是用户可配置的预算，不代表程序已获取当前模型的真实上限。
- 对未知兼容模型，输入采用 UTF-8 字节数加消息开销的保守估算，并预留输出与 1024 tokens 余量。预算包含系统提示、用户笔记、术语和相邻段上下文。不会只按原文字数判断，也不会静默截掉笔记。
- 上游明确报告上下文超限，或返回 `finish_reason=length/max_tokens`，普通纪要会进一步拆分输入；不能安全拆分时报告失败。
- 分段纪要按预算逐层合并，合并继承语言、模板、术语和笔记。决策、待办和未解决问题保留分段中的原文与出处并做精确去重。合并无法在预算内完成或结构校验失败时，按顺序保留有效分段，不发送无上限的最终合并请求。
- 原文精整遇到输出截断或上下文超限后，会自动把失败分段继续拆小；单条长发言也能拆分，以临时来源编号分别处理，再验证并恢复原来源编号。数字完整性等检查连续失败时，也会自动拆小；数字纠正重试提示会明确列出需要恢复及不能新增的数字，不降低检查标准。拆分深度和最小片段有界，不无限重试；小到无法再拆的片段仍被截断时会明确报错。
- 精整拆分策略和已通过检查的子段分别保存检查点，后续失败后续跑不会重复提交已知超长的父段。仅完整、通过验证的正文会成为正式纪要。
- 原文精整仍使用来源编号覆盖检查以及现有数字、单位、英文名称、否定和条件检查；它不经过摘要合并。格式与规则检查不能证明语义完全忠实，重要内容仍需核对文字稿。

## 流式、取消与异常

- 默认接收 SSE，解析分片 UTF-8、注释、usage 事件及结束原因；普通 JSON 响应也可接收。只有明确的正常结束才接受流式结果，截断或提前断流不会保存为正式纪要。
- 兼容接口明确拒绝流式时回退为普通请求。明确要求 `max_completion_tokens` 或不支持自定义温度时调整参数，并在本次任务后续请求中复用能力信息。
- DeepSeek 官方接口的 `deepseek-flash` / `deepseek-v4-pro` 原文精整请求显式设置 `thinking.type=disabled`。这些双模式模型默认开启思考模式，思考内容与正文共用输出预算；不把该厂商参数发送给其他服务或不支持的模型。普通纪要保持默认模式。
- 默认连接超时 10 秒、首个内容等待 120 秒、流式空闲等待 45 秒，每次调用的总期限为 600 秒。思考内容也视为模型活动，持续思考不会被首个正文等待期限误判为停滞；仅有心跳或元数据不能重置活动期限。总期限覆盖兼容回退、重试和服务端建议的等待时间。
- 暂时性网络错误、超时、断流及 HTTP 500/502/503/504 最多额外尝试一次；限流型 429 遵循 `Retry-After`。鉴权、余额和配额问题直接报错。
- 重试前清除本次请求的旧预览，避免两次输出混在一起。取消通过线程安全的任务取消机制关闭本地请求，也能中断尚未返回响应头的等待；不能承诺服务端停止计算或计费。
- 重试提示区分连接异常、响应超时、断流、服务异常和限流。开始下一次请求时立即替换旧提示，随后根据实际响应显示等待、思考、接收正文和检查状态；不会在正常接收正文时继续显示旧的重试提示。思考文本不显示在预览中。
- 工作线程实例作为请求身份，迟到的旧任务结果和进度不能影响后启动的任务。仍在运行的线程保留引用直至结束。

## 检查点和界面

通过校验的结果保存到现有数据库的 `meeting_generation_cache` 表；检查点按会议和生成指纹隔离。指纹覆盖原文、笔记、语言、说话人、接口、凭据摘要、模型、模板、提示词和预算。修改这些输入后不会复用旧结果，凭据明文不会写进检查点。

失败或取消保留已完成的检查点，同配置重试或应用重启后可以续跑；正式纪要成功保存后清理检查点，主动重新生成会重新调用模型。删除会议也清理检查点，迟到的写入不能复活会议。

界面以最多约每 150 毫秒一次的频率展示可读预览，明确标注“尚未保存”，不展示 JSON 协议。预览不覆盖正式纪要；复制、导出仍使用已有正式版本。失败或取消后恢复正式内容。只有完整结果通过校验并确认保存成功后，才发出完成通知。

诊断日志记录模型名、输入/输出字符数、重试次数、耗时、HTTP 状态和服务端请求编号；重试记录异常类型或 HTTP 状态及等待时间，截断时额外记录正文与思考内容的字符数，不记录思考文本、密钥或完整会议正文。

## 排队与自动生成

- 纪要和原文精整一次只跑一个任务。手动和自动任务都记在 `meeting_generation_queue` 表里，退出或崩溃后下次启动继续；已通过检查的分段由上面的检查点复用。
- 顺序：手动点的排在会后自动任务前面，同类按入队先后。手动请求不打断正在运行的任务，排在它之后；排队时会议页显示位置，可「取消排队」。删除会议同时移除它的任务。
- 自动生成默认关闭（`meeting.auto_generate`）。打开后，会议结束、接口已配置且文字稿至少 200 字时，按 `meeting.template_id` 入队。开关已关闭或会议已有纪要（包括手写的）时，等待中和失败的自动任务会被移除，不会覆盖用户内容。
- 远程端点：自动任务从不弹窗。打开开关时确认远程主机，每个任务启动前再检查一次；接口改成未确认的主机时不发送，记为失败，由用户在会议页确认后手动生成。
- 失败分两类。连接异常、超时（含总期限）、断流、HTTP 408、非额度类 429、500/502/503/504 视为暂时性故障：自动任务在 1 分钟、5 分钟后各重试一次，之后保留为「自动生成失败」。鉴权、余额、配额、请求或响应格式错误、未确认主机直接记为失败，不再重试。自动任务失败时托盘和会议页显示原因，点「生成纪要」手动重试；等待重试期间可「立即重试」。手动任务失败直接提示，不留在队列里。
- 本机模型（`localhost`、`*.localhost` 和回环地址）与实时识别争用 CPU / GPU：会议进行中不启动自动任务；新会议开始时让出正在运行的自动任务，已完成的分段保留，会议结束后继续。局域网和远程模型不受影响，手动任务也不让出。
- 会议列表标出「纪要生成中 / 纪要排队中 / 纪要生成失败」。主窗口没打开时，会议结束会提示纪要正在后台生成，生成完成或失败另有托盘提示。

## 验证方式

使用 HTTPX MockTransport 和真实 Qt 控件执行离线测试，覆盖断流、分片中文、输出截断、限流/配额、接口兼容、总期限、取消、失败续跑、缓存失效、数据库重启、旧请求隔离、分层合并和预览恢复。额外覆盖全部内置模板重试后清除旧提示、连续思考不误触发首字超时、心跳不能掩盖停滞、持续思考时的总期限及活跃流式输出中的取消。排队部分替换生成器调用，覆盖连续多场按序生成、手动插队、暂时性故障退避重试与最终失败、永久失败不重试、本机模型让路、未确认主机不发送、取消与删除后启动下一场、不覆盖已有纪要和重启续跑。不调用用户的付费模型接口。

`tests/fixtures/refinement_20261019.txt` 保存本次截断问题的复现原文，用于离线模拟反复截断：自动缩段后必须完整恢复所有原文和来源编号，不能丢段、重复或改用摘要。
