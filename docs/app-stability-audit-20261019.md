# 2026-10-19 应用稳定性与交互检查

范围：历史、会议、通用、引擎、AI 服务、关于，以及录音转写编排、纪要生成、取消、模型下载、更新和退出。
所有新增负载与界面检查使用隔离配置、临时数据库和虚构文字，没有录制环境声音、读取用户会议或调用付费模型接口。

## 修复的问题

| 问题 | 处理与验证 |
| --- | --- |
| 返回历史页、会议页时反复销毁并创建整张列表，大量控件重复布局和绘制 | 依据记录内容、日期显示及主题复用列表；实际数据变化时重新构建。详情单独刷新，摘要未变化时也能显示正文修改。历史正文结合文档版本避免重复替换，保留选中文字；行样式不变时不重复应用样式表 |
| 长会议每增加一条发言，就替换和重新解析整篇实时文字稿 | 正常新增发言只追加新段落；旧内容被修正、说话人更名或主题变化时仍完整更新。回归检查要求新增内容不删除既有文档字符、不重复追加，并保留选择与阅读位置 |
| 润色线程已结束，但排队的旧结果可能在取消或新任务开始后到达 | 结果与错误必须来自当前工作线程；无当前任务及已销毁发送者的回调直接忽略。纪要生成的回调也补齐空任务检查 |
| 下载报错后就释放工作线程、清理时阻塞等待、模型卡片重建后仍更新旧卡片 | 工作线程保留到真正结束；取消清理返回事件循环；进度更新查找当前卡片。用真实 QThread 验证错误已报告但线程尚未退出时仍保有引用 |
| 限时等待后直接退出 Qt，原生加载或网络线程可能仍在运行 | 先停止采集、取消任务、停止定时器并完成已有数据库写入；事件循环继续处理线程收尾，每 80 毫秒检查一次，线程结束后才退出。原生线程不强制终止 |
| 退出期间迟到的音频、识别和输出回调可能重启工作、继续粘贴或访问已关闭的历史库 | 清空已确认放弃的队列，入口忽略退出后的回调，关闭期间不重新打开主窗口。拒绝退出的原有流程仍保留待处理内容 |
| 更新下载无法协同取消，退出后仍可能更新检查结果或提示失败 | 更新下载在下一个进度检查点取消，不发送成功结果；退出后忽略检查结果与失败提示，校验下载文件完整性的原有逻辑保留 |
| 开始会议的三个下拉选项缺少可见字段名 | 增加“音频来源、转写模型、识别语言”及关联标签，避免“与转写相同”含义不明确；复查小屏与高缩放布局 |

## 本机负载测量

Python 3.10.11，PyQt6 6.11.0，Windows；实际 Qt 控件与 SQLite。
数据为 600 条历史、60 场会议和 1200 段长会议发言。页面切换各测四次，实时追加与整篇替换交替各测四次。
测量包含操作后事件处理和绘制；期间机器上也有回归检查运行，结果用于对照这次修改，不代表所有设备的延迟上限。

| 操作 | 优化前/对照的中位耗时 | 优化后中位耗时 |
| --- | ---: | ---: |
| 切回历史页 | 3389 毫秒 | 30 毫秒 |
| 切回会议页 | 1331 毫秒 | 40 毫秒 |
| 长会议追加一段发言，同次运行对照 | 整篇替换 285 毫秒 | 追加 58 毫秒 |

其余四个页面的切换中位耗时约 11–24 毫秒。首次进入历史页约 361 毫秒、会议页约 153 毫秒，包含首次布局和绘制。
四次追加检查中，已有文档删除字符数均为 0；整篇替换对照每次删除约 20.5 万字符。

原始记录：`build/diagnostics/app-audit-runtime-before-list-cache.json`、`build/diagnostics/app-audit-runtime.json`。
测量脚本：`build/diagnostics/audit_app_responsiveness.py`。这些为本地诊断产物，不进入发行包。

## 使用范围

本次已验证源码层面的回归、离线负载和界面显示。没有执行真实麦克风或系统音源长时间采集、大模型数小时推理、真实跨应用输入、安装更新包或重建安装版。
实际设备驱动、原生模型库和在线服务仍需要实机持续验证，测试通过不能证明所有环境都绝不崩溃。
不能即时中断的原生加载或网络读取可能延后进程真正退出；等待期间不销毁仍在运行的线程。
当前改动需要重新打包并在安装版验证后才会影响已安装的应用。
