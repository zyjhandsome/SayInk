# SayInk — 语音转文字桌面工具

本地离线的**口述输入**工具：**按住快捷键说话，松开后识别并粘贴到光标处**（默认），本地 ASR 识别，可选大模型润色。也可切换为 **自动持续转写**（按住开始整场监听，停顿后自动出字），或采集**电脑播放声** / **混合**来听会议——这两种来源下结果**只记录到历史、不粘贴**，不会误输入到当前窗口。开会请用独立的 **AI 会议记录**：本机实时转写并区分说话人，结束后用你配置的大模型生成**会议纪要**（摘要、要点、决议、待办、问题、时间线），不保存音频。

版本号以 **`sayink/version.py`** 中的 `__version__` 为准（当前 **2.2.11**）；安装包文件名、Inno 元数据与 Windows 下 `SayInk.exe` 属性均与之同步。

> **原名 VoiceInk。** 从 VoiceInk 升级：安装 SayInk 会先卸载旧版 VoiceInk，并把 `~/.voiceink`（设置、历史、已下载模型）整体改名为 `~/.sayink`，凭据管理器里的 API Key 也会自动迁移；无需重新配置或重新下载模型。

## 功能一览

### 两种触发方式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **按住说话**（默认） | **按住**说话，**松开**识别并粘贴；录音中 **Esc** 取消。松开后听写条立即转为「正在识别」；上一句还没识别完时再按住会提示「请稍候」，不会把两句合并，此时按 Esc 也不会丢掉上一句 | 日常口述输入、短句、精确控制 |
| **自动持续转写** | **按住快捷键**开始整场监听；停顿后自动识别、输出；**Esc** 或听写条 **结束** 结束整场（进行中片段仍会完成） | 会议、长口述、连续输入 |

已有安装升级后保持原来的触发方式；默认值只影响新安装。

- 默认快捷键 **Alt+X**，左右 Alt 都可以；可在设置 → 通用 中更改。Windows 上按住快捷键时，主键（如 X）及其自动连发**不会**传给当前软件，Alt 组合松开时也不会激活菜单栏。因此 SayInk 运行时，Word / OneNote 里 Alt+X 的「Unicode 码转字符」会失效，需要这个功能请换成别的快捷键
- 若改用 **Shift+字母**（如 Shift+X）：**短按**（不到 0.18 秒）仍会正常输入大写字母，不会弹「录音过短」提示，左右 Shift 都可以，先松 Shift 再松字母也一样
- 为避免占用常用组合，Ctrl+C / Ctrl+V / Alt+Tab / Win+L 等不能设为录音快捷键
- 录制快捷键时支持字母、数字、Space 与 **F1–F12** 配合修饰键；录制中按 **Esc** 只是取消录制、保留原快捷键（Esc 本身用于取消 / 结束，不能作为录音键）
- 防误触：按住说话约 **0.18 秒**，持续转写约 **0.30 秒**；持续模式下**松开快捷键不结束**整场监听；短按不显示听写条
- **允许 Esc 结束持续转写**可在设置 → 通用 → 录音与输入 中关闭，此项仅在持续转写模式显示；关闭后在其他软件里按 Esc 不会中断监听，用听写条「结束」停止。结束后已录内容继续识别；按住录音时 Esc 则取消本次录音、不保留本次内容。听写条的提示和按钮说明会同步这一偏好

### 音频与识别

| 来源 | 说明 |
|------|------|
| 仅麦克风 / 电脑声音 / 混合音源 | 16 kHz 单声道；设置中 **测试声音** 验证设备 |

- 引擎 **sherpa-onnx**（≥ 1.13.8），本地离线识别；内置 **9 款模型**，默认 **Fun-ASR-Nano**（约 950 MB）
- **已下载 ≠ 已载入**：每次冷启动须载入内存（Fun-ASR-Nano 约数十秒），等托盘「就绪」后再用。只有当前启用的模型会载入；再下载一个模型时，完成提示会说明它尚未启用，需在模型卡片点「使用此模型」切换
- 持续模式按停顿 **VAD 切分**；一口气说满 **15 秒**仍没有停顿时，会在最近约 3 秒里**最安静的时刻**切开，而不是在词中间硬切；按住说话超过 15 秒的长句同样在安静处分片识别后拼接，拼缝处容忍两次解码的个别字差异。结束监听会 **flush 收尾句**。每段按顺序走完「识别 → 润色 → 粘贴 → 写历史」后才处理下一段，开启润色时也不会丢段或串段。每段在切出时就固定所属场次、序号和音频来源，结束后立刻开新场，上一场排队的片段仍写入上一场
- 识别或润色跟不上说话时，已切出的语音在内存中排队；排队超过约 **3 分钟**的语音会自动暂停监听并提示，已录下的内容继续处理、不丢弃，处理完可再次开始
- 监听中麦克风被拔掉或设备失效，约 3 秒内提示「音频设备已断开」并结束本场（已切出的片段照常识别）
- 冷启动载入模型时，听写条显示该模型**上次载入用时**（首次为约 10–40 秒）
- **预期延迟（本机实测，CPU 推理，4 线程）**：Fun-ASR-Nano 的实时率约 **0.5–0.8**，即说 6 秒大约要算 3–5 秒；按住说话是松开后开始算，持续转写还要先等约 **1.20 秒**静音判定再开始算（不到 0.8 秒的短句会多等到约 1.8 秒，好和后面的话合成一段识别）。所以一句话说完到出字通常是 **几秒**，不是即时字幕。润色会再加一次大模型往返。数值来自一台 Intel Core Ultra 9 185H 笔记本，更慢的机器会按比例变长
- **（实验性）** 持续转写一场里出现至少两个不同声音时，**历史**按「说话人 1」到「说话人 8」标出这一场；光标处粘贴仍是纯文字。结束再开一场会从 1 重新编号，不记住是谁。混合采集时，能分清来自麦克风还是电脑播放的段落会一并标出来源。接话中间没有停顿时，仍是一段、一个人。说话人区分**与会议记录共用同一套方法**：下载了「说话人嵌入 CAM++」就按声纹判，没下载退回频谱特征；3 秒内接着说且声音相近的段落沿用上一位、过短的段落不单独判人；一场结束、最后一段写完历史后再对整场重新聚类一次并改写编号。没有声纹模型时，背景噪声、换麦克风或音量变化仍可能把同一个人拆成两个编号，尚未用真人多人会议评估准确率，请勿当作可靠的发言人记录
- 单次转录、连续转录与会议共用 设置 → 通用 → **识别** 里的**识别语言**与**自定义词汇**（热词）；**语音分段**和说话人增强放在默认折叠的**高级识别设置**中。Silero VAD 成功加载后用于三种模式；未下载或加载失败会自动回退能量断句。高级设置明确显示**未下载 / 正在加载 / 已加载并生效 / 加载失败并回退**，可直接下载 Silero；引擎页的「已下载」仅表示文件存在。单次转录在内部按停顿分段识别，仍在松开快捷键后统一输出；连续转录与会议按段输出，默认停顿分别为 1.2 秒与 1.5 秒，最长分段都是 15 秒。本次不增加高级调参。混合采集下三种模式都会自动配平两路音量。公共识别、辅助模型下载及模型切换在录音或处理语音期间会延后到本场结束、已录语音处理完成后生效，页面提示「已保存，待生效」；折叠高级设置后仍能看到等待状态或加载失败，不为应用这些更改中断采集或丢弃排队语音。共用能力与模式边界见 [`docs/shared-recognition.md`](docs/shared-recognition.md)
- 结果自动去掉 `<asr_text>`、`<sil>`、`<|zh|>` 等识别器自身的标记；用户口述的 `<div>`、`<br>` 之类正常保留
- 中文为主的话里混进的无关外语短句（多语种模型偶发的乱码式输出）会被过滤，但整句都是日语 / 韩语时原样保留

| 模型 | 特点 | 约体积 |
|------|------|--------|
| **Fun-ASR-Nano**（默认） | FunASR 端到端模型，中/英/日 + 方言 | 950 MB |
| FireRedASR2 | 侧重中文，含方言，速度适中 | 740 MB |
| FireRedASR2 AED | FireRedASR2 编解码版，含方言，较慢 | 1.2 GB |
| Qwen3-ASR 1.7B / 0.6B | 阿里大模型 ASR，多语种 | 2.4 GB / 983 MB |
| Paraformer 中文 / 三语 | 体积小，中英 / 中英粤 | 240 MB |
| SenseVoice | 速度快，多语种 | 230 MB |
| Zipformer CTC | 轻量中文 | 367 MB |

引擎页的「精度 / 速度」星级是维护者按上游模型说明和日常试用给出的粗略参考，本仓库没有公开的统一评测（样本、硬件、测量方法）。准确率随口音、领域用词、麦克风和噪声变化很大，选型请用自己的几段真实录音对比；机器较弱或更在意出字速度时优先试体积小的模型。想用数字说话，`tools/asr_bench.py` 可以在本机对几款模型跑同一组录音，输出字错率、热词命中率与实时率。默认先按会议的 Silero 断句再逐段识别，和开会时的切段一致（见 [`docs/asr-benchmark.md`](docs/asr-benchmark.md)）。说话人拆人 / 并人的标法见 [`docs/meeting-speaker-eval.md`](docs/meeting-speaker-eval.md)，目前还没有真人结果。

### AI 会议记录

独立于听写的「会议」流程：**托盘 → 开始会议**，或主窗口 **会议** 页右上角「开始会议」。设计依据见 [`docs/meeting-notes-design.md`](docs/meeting-notes-design.md)。

- **开始**：默认弹出一张信息卡（标题 / 参会人 / 议程 / 音频来源 / 识别模型 / 语言，全部可空），可在 设置 → 通用 → **会议默认设置** 关掉改为直接开始。会议音频来源默认**跟随听写设置**，也可单独指定麦克风、电脑播放或混合；已有安装保存过的独立会议音源会保留。识别模型默认与听写相同。开始卡片会显示跟随的当前音源，卡片上的音源、模型和语言修改**仅用于本场**，不改写默认设置或公共识别配置
- **进行中**：听写条显示「会议中 · 计时」，左键点听写条打开会议页，「标记」按钮或会议页「标记此刻」记下重要时刻（可带备注）；会议页实时按说话人逐条显示文字，右侧可随手记笔记。会议期间 **听写快捷键暂停**（按了会提示「会议记录中」），**Esc 不会结束会议**；只能用听写条「结束」、托盘「结束会议」或会议页「结束会议」收尾。结束会先把排队的语音识别完再归档
- **文字稿**：每句话带相对时间戳与「说话人 N」，写入 `history.db`（`trigger_mode = meeting`），**即使关闭了语音历史也会保存**；不出现在历史页列表里，不受历史保留天数 / 最大会话数清理，也不被「清空全部历史」删掉——只能在会议页逐场删除。不保存音频，也不保存声纹
- **暂停与核对**：会议页可「暂停采集 / 继续采集」。手动暂停期间不采集新音频，已录内容继续识别，不会自动恢复；继续后仍是同一场会议。主窗口侧栏持续显示本场音源、录制或暂停状态及会议保存去向，切换页面后仍可查看。实时文字稿更新保留选区和阅读位置，停在底部时才跟随最新发言。`Ctrl+F` 在会后列表搜索会议，在进行中查找本场文字稿；搜索无结果提供清除入口。会议开始卡与笔记区支持滚动，小屏幕下开始、暂停、继续和结束操作保持可达
- **说话人**：**说话人嵌入 CAM++**（约 28 MB）用于连续转录与会议的说话人增强，**Silero VAD**（约 2 MB）用于三种模式的断句。公共识别页可开关 CAM++ 增强并查看实际加载或回退状态；单次转录无需区分说话人。第一次开会若还没下载，会问一次「下载后开始 / 直接开始」；之后开始卡片和进行中页面都保留「下载辅助模型」按钮（会中下载对下一场生效），引擎页也能下载。没下载或加载失败时退回频谱特征与能量断句；手动选能量断句或关闭 CAM++ 时不会误报模型缺失。无论哪种方式，紧接着上一句（3 秒内）且声音相近的段落沿用上一位说话人、过短的段落不单独判人，会议结束时再对整场重新聚类一次；会议页可把「说话人 2」改成真名，文字稿与纪要同步替换
- **识别参数**：术语表（最多 50 条、每条 20 字）会作为**热词**传给支持的模型（Fun-ASR-Nano、Qwen3-ASR）；识别语言会传给支持的模型（Fun-ASR-Nano、SenseVoice）。两者对听写同样生效。不支持的模型只把术语交给纪要模型。无论哪个模型，识别结果里只是大小写不同的英文术语（如 FireRedASR2 输出的 `GITHUB`）都会改回术语表的写法。会议段落**不逐句润色**（`meeting.polish_segments`，默认关）
- **纪要**：会议结束后在会议页选模板（通用 / 站会 / 一对一 / 客户沟通 / 评审）点「生成纪要」。使用 设置 → AI 服务 → 接口配置 的地址与密钥（与润色共用，关闭润色时也一直可填），可在 AI 服务 → 会议纪要 单独指定更大的模型并测试连接、设默认模板与输出语言；不需要开启「文字润色」。没配置时会议页的按钮显示「配置 AI 接口」，点击直接跳到接口配置。会议页与 AI 服务页的「管理模板」支持新建、复制、编辑、删除自定义模板，可配置名称、整理要求、输出形式与章节；内置模板可复制后修改。远程端点第一次生成前会确认（只发文字稿，不发音频），确认后记住该地址。超过约 1 万字的文字稿分块生成再合并；纪要里找不到文字稿依据的内容标「（待核对）」，没内容的小节写「本场未识别到」
- **原文精整**：会议模板可选「原文精整」，点击「整理原文」将多人的原始转写逐段、逐句融合为通顺、逻辑清晰的书面文章。保留业务细节、情绪、主观评价、个人口吻、条件及不同观点，仅去除口吃重复、纯粹口语赘词和无效寒暄；按人物、规划和话题变化细致分段，不按说话人或识别切片机械分段，不反复添加「某某表示」等转述套语，不生成摘要、标题或列表，始终保留原文语言。与纪要共用接口和模型，不需要开启文字润色。长文分块精整后直接拼接，不再摘要合并；检查来源片段覆盖、数字与单位、英文名称、否定和条件表达及明显压缩，输出截断或检查失败时重试一次，仍失败则保留当前版本并提示。规则检查不能保证完全无损，人名、观点归属等重要内容仍应对照文字稿核对。生成后可编辑、复制精整正文、导出；与纪要共用当前结果位置，重新生成会替换当前内容，可恢复上一版，模板与模型信息同步恢复。
- **阅读与核对**：纪要显示「AI 生成 / 已手动编辑」和所用模板；时间戳跳到对应文字稿并高亮，可「返回纪要」回到原阅读位置。连续发言按说话人归组，姓名明确标注为手动命名。空的决策 / 待办章节在阅读时收为简短提示，导出保留原文。
- **说话人纠错**：「命名说话人」修改整组发言的显示名称；「纠正发言人」可把某一段改归其他说话人或新增编号，只修改该段，其他发言保持原归属。更正仅在会议结束后、纪要生成未运行时可用；已有纪要保留，并提示核对发言归属，重新生成后更新来源状态。
- **编辑与导出**：纪要用「保存修改」明确保存，切换会议、离开页面或开始新会议前也会自动保存；保存失败时保留草稿并提示。复制按钮随当前内容显示「复制纪要 / 复制文字稿 / 复制草稿」，文字稿不依赖生成纪要即可复制。导出可选仅纪要、仅文字稿或完整会议记录，编辑中使用当前草稿。模板选择表示下次生成使用的模板，刷新保留选择，重新生成仍有替换确认并可在「更多 → 恢复上一版纪要」找回上一版；标题可在会议页改。
- **异常**：设备断开或识别积压过长时**暂停采集而不结束会议**，会议页可「继续采集」；积压处理完会自动继续。程序崩溃时未结束的会议下次启动标记为「已中断」，仍可生成纪要。会议进行中退出程序会单独确认
- 会议期间保存的音频 / 引擎设置、托盘切换模型都会等会议结束后再生效

### 输出与润色

- **结果去向**（设置 → 通用 → 录音与输入，与音频来源相邻）：可选「自动（随音源切换）」「输入当前光标」「仅保存到历史」。自动模式下，麦克风默认输入光标，电脑声音或混合音源默认仅保存历史，并在控件旁显示当前实际去向；两种固定选择都会在切换音源与重启后保留，可随时重新选择自动。仅保存历史但历史已关闭时，就地显示不会保存的原因及「开启转写历史」按钮，听写条同步提示「未保存 · 历史已关闭」。剪贴板恢复选项只在输入光标时可用
- **声音测试**临时采集约 2 秒，不保存音频或转写文本；显示本次实际打开的设备、输入音量，以及无输入、音量偏低、偏高或设备错误。混合输入的总体有声结果不代表两路都成功，降级提示会保留。切换音源或设备后会清除旧的测试结论；「设备恢复自动选择」只重置设备，不修改音源或结果去向
- **自动粘贴**到光标处；无法确认成功时降级为「已复制到剪贴板」（不误报「已输入」）。目标窗口以管理员权限运行时（系统会拦截模拟按键），直接提示「已复制」，不发送粘贴键
- 发送粘贴键前会再次确认前台仍是开始输出时的窗口；等待期间切到了别的窗口，就不发送粘贴键，只把文字留在剪贴板供手动粘贴，避免误输入到新窗口
- Windows 上发送 Ctrl+V 时，若快捷键里的 Shift / Alt / Win 还被按着，会先抬起再补回，避免被目标软件当成 Ctrl+Shift+V 等别的组合
- 「已发送」表示已发送粘贴快捷键，无法证明目标控件已插入文字；请核对目标应用。粘贴键发出后前台窗口随即变了，则提示「已发送 · 未确认」并把文字留在剪贴板。macOS / Linux 的粘贴命令返回失败时会降级为「已复制」
- 润色或粘贴卡住超时：润色阶段卡住就直接输出 ASR 原文；粘贴阶段卡住则提示「输出超时 · 已复制」，文字在剪贴板，可手动 Ctrl+V。两种情况都会继续处理排队的下一段
- 「粘贴后恢复剪贴板」在粘贴约 0.5 秒后才恢复，且只恢复文本；原剪贴板是图片等非文本内容时保留转写文字，不会清空
- 可选 **OpenAI 兼容 API** 润色（DeepSeek、通义、Ollama 等）；失败，或返回内容明显比原话长很多（像在回答而不是润色）、删改了原话里的数字（阿拉伯数字含零；「三万五」等中文数字换算后比对，单独的「一」不算）、少了否定词（不 / 没 / 别 / not 等）、丢掉了英文专名（如 GitHub、API）时，**输出 ASR 原文**。数字检查允许时间补 `:00`、千位分隔符和小数末尾零等格式变化。这是保守的规则检查，拦不住所有改义（例如中文人名被改写），重要内容请核对
- 按住说话模式下，上一句还在润色时可以开始录下一句；上一句润色失败时仍回退它自己的原文，不会被下一句影响
- Windows 上 API Key 保存在**系统凭据管理器**（「SayInk/llm.api_key」），不写入 `config.json`；旧版本配置里的 Key 会在启动时自动迁移。凭据管理器写入失败或读不出来时，Key 只在本次运行中有效，`config.json` 里残留的明文 Key 也会被清掉，AI 服务页会提示重启后需重新填写
- **主窗口**（侧栏：历史 / 会议 / 通用 / 引擎 / AI 服务 / 关于）收纳设置、历史与会议记录；听写只留一条薄 **听写条**。托盘与听写条共用 模型载入中 / 正在听 / 正在识别 / 润色中 / 已复制 / 会议记录中。托盘 → **打开 SayInk**（单击或双击托盘图标均可打开主窗口）；配置保存在 `~/.sayink/config.json`

### 工作台操作

- 主窗口侧栏显示当前运行状态、音源与触发方式；设置页提供即时保存提示。
- 从托盘退出或安装更新时，若仍在录音、识别、润色或有片段排队，会先询问。默认「返回继续处理」，Esc / 关闭确认框也会返回；可结束监听并等剩余内容处理完成后再退出。「放弃并退出」会丢弃尚未完成的内容。空闲退出不弹确认。取消更新安装后，已下载的包会保留，再次安装会重新校验 SHA-256，校验通过即可复用。
- **Ctrl+1…6** 切换六个页面，**Ctrl+F** 搜索历史，**Ctrl+W** 收到托盘；录制新快捷键时暂停这些导航快捷键。
- 双击标题栏最大化 / 还原，拖动任意窗口边缘或右下角调整窗口；历史页中间分隔条可调整阅读宽度。
- 历史按天分组，列表上方可**搜索全部听写历史**（原文与润色文本，不含会议）；结果预览显示命中段落和附近内容，首次打开命中关键词的版本。每条会话展示两行正文预览，模型等参数收在「详细信息」。超过 50 场可继续加载更早会话，搜索与选中会话在刷新后保留。
- 点「选择」进入带复选框的批量模式，也支持 **Ctrl / Shift 多选**；摘要与复制 / 导出 / 删除按钮均显示已选数量，并可一键 **合并** 多条会话（8 秒内可撤销）或 **转为会议** 进入会议工作台生成结构化纪要。「完成」返回单条预览。批量复制按时间从早到晚合并最终文本（有润色用润色版）。单条会话支持 **编辑**（保存为润色文本，原文保留不变）、事后 **润色 / 重新润色** 以及在「更多」菜单中 **转为会议并整理**。有润色结果时可切换「润色 / 原文」，**唯一的主复制按钮和 Ctrl+C 都复制当前查看的版本**；在正文中选中文字时 Ctrl+C 仍只复制所选部分。
- 单条删除位于详情「更多」菜单，也支持 **Delete**；删除或合并后 8 秒内可在底部提示条撤销。「清空全部听写历史…」位于列表「更多」菜单，确认框显示总条数，并明确包括未加载和搜索结果之外的记录、会议不受影响以及不可撤销。

### 历史

- 可选在本机保存转写历史；首次使用会询问是否开启，默认配置项为 `history.enabled`
- 历史写入发生在文本输出流程之后；保存 ASR 原文、润色后文本（如有）、音频来源、触发模式、模型、时长与目标应用**进程名**。持续转写的多人场次另存本场说话人编号（最多 8 人；一场结束后会按整场重新聚类改写一次），不写入粘贴文本，也不跨场保留声纹
- 托盘 → **历史** 打开主窗口并切到历史，可搜索、查看、复制原文 / 润色结果、删除会话，并导出 Markdown
- 历史保存在 `~/.sayink/history.db`（SQLite）；按「整场会话」管理，默认保留 **90 天**、最多 **5000 场**
- 会议的文字稿、标记、说话人名与纪要在同一个数据库里，但由「会议」页单独管理，不计入上面的清理与清空（见 [AI 会议记录](#ai-会议记录)）

### 平台

| 平台 | 状态 |
|------|------|
| Windows 10/11 | 主要平台：提供安装包，开发与自动化测试都在这里进行（系统声 / 混合最佳） |
| macOS | 源码有适配路径（需辅助功能权限；系统声需虚拟声卡），**尚未做系统验证** |
| Linux (X11) | 源码有适配路径（需 `xdotool`），**尚未做系统验证** |
| Linux (Wayland) | 仅部分功能；自动粘贴通常不可用，会降级为复制 |

macOS / Linux 只提供源码运行方式，没有安装包，也没有在真机上跑过完整流程；遇到问题欢迎反馈。主窗口的最小高度会按屏幕可用区域收缩，小屏或高缩放（如 1366×768 缩放 150%）时不会高出屏幕；最小宽度仍为 880 逻辑像素（历史页双栏所需），可用宽度更小的屏幕尚无紧凑布局。

## 快速上手

### 安装（Windows，推荐）

[Releases](https://github.com/zyjhandsome/SayInk/releases) 提供两种安装包，选一个即可：

| 安装包 | 大小 | 适合 |
|--------|------|------|
| **`SayInk-Setup-2.2.11.exe`**（轻量包，默认） | 约 72 MB | 首次安装、日常更新。已带说话人嵌入 CAM++ 和 Silero VAD。不含 Fun-ASR-Nano，首次启动的欢迎框会带你到 **设置 → 引擎** 下载（约 950 MB，只需一次） |
| `SayInk-Setup-2.2.11-full.exe`（完整包） | 约 740 MB | 安装后要立刻离线使用：Fun-ASR-Nano、说话人嵌入 CAM++、Silero VAD 随安装包装好 |

两种包装出来的程序完全相同；**应用内自动更新一律下载轻量包**。已安装的模型（无论是完整包带的 `安装目录\models`，还是自己下载到 `~/.sayink/models/` 的）在升级时都会保留，不必重新下载。无安装包见 [从源码打包](#从源码打包)。

### 从源码运行

```bash
pip install -r requirements.txt
python run.py
```

Windows 若 `python` 非 3.10，请用：

```bash
py -3.10 -m pip install -r requirements.txt
py -3.10 run.py
```

模型：**设置 → 引擎** 下载，或放到 `models/`、`~/.sayink/models/`。

### 首次使用

1. 等托盘 **「模型载入中」** 消失；持续模式就绪后**不会**再弹闲置「待开始」，请看托盘提示
2. 托盘 → **打开 SayInk**（Windows **双击**托盘打开主窗口；冷启动第一次落在「通用」）→ **测试声音**；确认触发方式
3. **按住说话**（默认）：按住 **Alt+X** 约 **0.18 秒** 说话 → **松开** 识别并粘贴
4. **持续转写**（可选）：设置 → 通用 切换后，按住 **Alt+X** 约 **0.30 秒** → 说话停顿约 **1 秒**后自动出字（不用点结束）→ **Esc** / 听写条 **结束**整场

### 操作指南

| 操作 | 按住说话（默认） | 持续转写 |
|------|------------------|----------|
| **按住快捷键** | 开始录音 | 开始整场监听 |
| **松开快捷键** | 结束并识别 | 不结束监听 |
| **Esc** | 取消录音 | 结束整场（可在设置中关闭） |
| **听写条「结束」** | 无此按钮（松开即出字，听写条随后自动收起） | 结束整场 |

> **快捷键无反应？** 确认不在「模型载入中」；持续转写需按住约 0.30 秒。默认 **Alt+X**，可在设置中更改。会议进行中快捷键会被暂停，听写条会提示「会议记录中」。

**会议记录：** 托盘 → **开始会议**（或主窗口 会议 页）→ 填信息卡（可跳过）→ 开会；需要时点听写条「标记」→ 听写条「结束」/ 托盘「结束会议」→ 会议页选模板点 **生成纪要** → 编辑 / 复制 / 导出。

**AI 服务（可选）：** 设置 → AI 服务 → 接口配置，填 API URL / Key / 模型名；文字润色与会议纪要共用这组配置，可分别开启。接口地址以 `http://` 或 `https://` 开头即可（无论是否开启润色，保存时都会检查；其它协议会被拒绝）。公网 HTTP 会明文传输密钥和转写内容。公网地址请填写 Key；本机或局域网端点（`localhost`、`127.0.0.1`、`192.168.x.x` / `10.x.x.x` / `172.16–31.x.x`、`*.local`，如 Ollama `http://localhost:11434/v1`）Key 可留空（留空时不发送 `Authorization` 请求头）。  
**历史（可选）：** 设置 → 通用 → 历史，可开关「保存语音历史」，并调整「保留天数」与「最大会话数」。关闭开关只停止未来写入，不会删除已有历史。  
**外观：** 设置 → 通用 → 外观，可选跟随系统 / 浅色 / 暗色；切换后立即作用于主窗口、听写条与托盘。

**模型目录：** 设置 → 引擎 → 存储位置 **更改**（默认 `~/.sayink/models/`；安装版的安装目录普通用户不可写时，新下载的模型一律放到这里，安装包自带的模型仍可直接使用）。  
**下载源：** 设置 → 引擎 → 下载 → 下载源。默认「自动」先连 Hugging Face 官方，连不上时改用 hf-mirror 国内镜像；也可固定其中一个。每个模型都锁定在模型仓库的某个固定提交上，每个文件下载后都要核对大小和 SHA-256（固定值写在 `sayink/speech_recognizer.py` 的模型表里）：不完整或内容不符的文件不会保留；自动模式下会改从另一个来源重下。

## 从源码打包

**Windows 10/11**，Python 3.10+。生成安装包还需 [Inno Setup 6](https://jrsoftware.org/isdl.php)。默认打出的是**轻量包**（带说话人嵌入 CAM++ 和 Silero VAD，不含 Fun-ASR-Nano）；加 `--with-model` 打**完整包**，再带上 **Fun-ASR-Nano**。两种包装前，对应模型都要已在本地。

```bash
pip install -r requirements-build.txt -c constraints-windows-py310.txt   # 运行依赖 + PyInstaller，按已验证版本固定
python -m sayink_build.dependency_check                 # 打包前检查依赖版本
python sayink_build/download_bundle_model_for_build.py   # 把 Fun-ASR-Nano、CAM++、Silero VAD 下载到 ./models/
python build_release.py                 # → dist/SayInk-Setup-<版本>.exe（轻量包，约 72 MB，含 CAM++ 和 Silero VAD）
python build_release.py --with-model    # → dist/SayInk-Setup-<版本>-full.exe（完整包，再含 Fun-ASR-Nano）
# 或仅便携版：
python build.py                         # → dist/SayInk/SayInk.exe（须整目录分发；加 --with-model 再带 Fun-ASR-Nano）
```

`build_release.py` 打包前会做发布检查（`sayink_build/release_gate.py`）：已跟踪文件没有未提交改动、源码目录没有未跟踪文件；远端 `v<版本>` tag 指向当前提交；该提交的 `tests.yml` CI 已通过。任何一项不满足就停止打包。所以发版顺序是：提交并推送 → 等 CI 变绿 → 打 tag 并推送 → 打包 → 上传。本地试打包加 `--skip-release-checks`，这种产物不得发布。

发布时把两个安装包都上传到同一个 Release；应用内更新器按文件名 `SayInk-Setup-<版本>.exe` 挑轻量包（`sayink/updater.py`），找不到时才退回同版本的其他安装包。便携版须整目录分发 `dist/SayInk/`。

## 变更审查清单（必读）

> **规则：** 每次功能新增、行为修改或 Bug 修复合并前须：读 diff → 确认本 README 用户向描述仍准确 → 核对架构/信号未破坏 → 跑测试 → 手工冒烟 → 在 PR 中记录结论。不得只改代码不更新文档，不得只改文档不跑验证。

**最低验证：**

```bash
py -3.10 -m pytest tests/test_readme_features.py tests/test_theme_resolve.py tests/test_ui_styles.py -q
```

**全量测试与验证环境：** Windows x64 / Python 3.10 使用已验证的固定依赖约束：`python -m pip install -r requirements-dev.txt -c constraints-windows-py310.txt`。其他平台使用 `requirements-dev.txt`。设置 `QT_QPA_PLATFORM=offscreen`，运行 `python -m pytest -p no:cacheprovider tests -q`。`tests/conftest.py` 让整个测试会话跑在英文 Windows 代码页（cp1252，与 CI 运行机相同）上，并把用户目录和 `%APPDATA%` 指向临时目录：中文开发机上的结果与 CI 一致，测试也不会读写真实的 `~/.sayink`。唯一加载真实模型的检查（Silero VAD）默认跳过；想在本机跑，把 `SAYINK_REAL_MODELS_DIR` 设为应用的模型目录（如 `%USERPROFILE%\.sayink\models`），它只读取、不写入。

GitHub Actions 的 `.github/workflows/tests.yml` 会在 push / PR 时执行 `ruff check`（配置见 `ruff.toml`，只查语法错误、未定义 / 未使用名称等硬错误）、Windows 回归、`pip check` 与发布依赖检查。本地可用 `python -m ruff check sayink sayink_build tests build.py build_release.py run.py`。`python -m sayink_build.dependency_check` 核对当前环境与 `requirements.txt`；`build.py` 也会先检查依赖，再清理旧构建目录，低于要求的引擎不能继续打包。固定约束覆盖 Python 包版本，不包含 Windows 系统组件或安装包签名；模型权重另由模型表里的固定提交和 SHA-256 锁定，`build.py` 打包前会逐个校验这次要带上的模型文件。

记录结论时写明 Python、PyQt6、sherpa-onnx 版本：sherpa-onnx 低于下限（1.13.8）的环境只能证明测试里的应用逻辑，不能代表发布依赖。发版前仍应在干净环境中跑全量测试，并冒烟安装包。当前可靠性优化与验证记录见 [`docs/reliability-first-pass.md`](docs/reliability-first-pass.md)。

**必守行为（摘要）：**

| 级别 | 要点 |
|------|------|
| **P0** | 粘贴不假成功（含管理员窗口）；等待期间焦点切走不发送粘贴键；持续模式收尾句不丢；开启润色时持续模式逐段输出、不丢段不串段，排队片段不串场；润色失败或数字被删改时回退本句原文；未完成转写退出须明确确认放弃，安装更新不能先启动安装包再确认；API Key 任何情况下不以明文写入 `config.json`；自动更新必须有 SHA-256；加载中不被其它错误盖住；发行版日志写入 `~/.sayink/logs`；会议：不保存音频与声纹，文字稿不随历史清理 / 清空丢失，Esc 与听写快捷键不会结束会议，会议文字只进历史库不粘贴，纪要只发文字稿且远程端点首次需确认 |

| **UI** | 默认 `appearance.theme_mode=dark`；切换浅/暗/系统后主窗口、听写条、托盘一致换肤且无需重启；设置控件对齐在 light/dark 下仍成立 |

## 常见问题

**Q: 选好模型了，为什么启动还要等很久？**  
A: **下载/选好** ≠ **载入内存**；默认 Fun-ASR-Nano 冷启动约数十秒。等托盘「就绪」再按热键。

**Q: 托盘已就绪，听写条还在加载？**  
A: 正常应同步；以听写条为准，加载完成前勿按热键。

**Q: 如何转写电脑播放的声音？**  
A: 设置 → 通用 → 录音与输入，音频来源选「电脑声音」或「混合音源」。结果去向为自动时，会仅保存到历史，在历史页看结果；需要输入光标时，在相邻的「结果去向」中固定选择「输入当前光标」。Windows 建议 `PyAudioWPatch` 或立体声混音 / VB-Audio。

**Q: 自动持续转写怎么用？**  
A: 设置 → 通用 → 录音 选「持续转写」。按住 **Alt+X** 开始；说话停顿约 **1 秒**后自动输出，不用点结束；**Esc** 或听写条 **结束** 停止整场。开会选「混合」并配合「只记录到历史」。

**Q: 开会想要一份纪要，该用持续转写还是会议记录？**  
A: 用 **会议记录**（托盘 → 开始会议）。持续转写只是把话写进历史；会议记录会带时间戳、区分说话人，结束后一键生成纪要，期间听写快捷键和 Esc 都不会误碰停掉。纪要用的是 设置 → AI 服务 里的大模型接口（不用开启润色），没配置也能先保存文字稿，配好后再生成。

**Q: 会议纪要里的「（待核对）」是什么意思？**  
A: 模型写的这句在文字稿里找不到对应原话，可能是概括过头或听错。核对后可直接在会议页编辑纪要，或换个模板重新生成。

**Q: 会议没区分出说话人 / 把一个人拆成了两个？**  
A: 2.2.7 起轻量包和完整包都带上 CAM++ 和 Silero VAD。更早的轻量包要在开始卡片或进行中页面上点「下载辅助模型」（约 30 MB），或到 设置 → 引擎 下载；下一场会议和下一场持续转写都自动启用。没有它时只能按频谱粗分，同一个人换个说法、音量一变就可能拆成两个编号；程序会让 3 秒内接着说的相近段落沿用上一位、过短的段落不单独判人，并在会议结束时重新聚类一次，但仍不如声纹模型。结果仍不满意可在会议页把编号改成真名，文字稿和纪要会一起改。

**Q: 会议中电脑卡了、麦克风掉了，内容会丢吗？**  
A: 已识别的句子已经在本机数据库里。设备断开或识别积压太长时只暂停采集，会议页点「继续采集」即可；程序崩溃的话下次启动这场会标为「已中断」，仍可生成纪要。

**Q: 说完要等几秒才出字，正常吗？**  
A: 正常。识别在本机 CPU 上跑，实时率约 0.5–0.8：6 秒的话大约算 3–5 秒；持续转写还要先等约 1.2 秒静音确认这句说完。开着润色会再加一次大模型往返。想更快可以换更小的模型（设置 → 引擎）或关闭润色。

**Q: 混合模式只有麦克风？**  
A: 刷新设备列表，检查系统声设备；测试时同时说话并播放电脑声音。

**Q: 短按快捷键没反应？**  
A: 按住说话需约 **0.18 秒**，持续转写约 **0.30 秒**；短按不会进入。

**Q: 持续转写在有风扇声 / 底噪的环境里一直不出字，或者每隔 15 秒才出一大段？**  
A: 分段门限会跟着最近约 8 秒里最安静的时刻自动抬高（最多到固定上限），稳定的底噪不再被当成一直在说话；不到 0.2 秒的敲键、咳嗽等瞬响也不会单独成段。若环境噪声本身就接近说话音量，请靠近麦克风或降低噪声。

**Q: 结果里有 `<asr_text>` / `<sil>`？**  
A: 应自动清洗；若仍出现请升级至最新版。

**Q: 打包提示缺少 Fun-ASR-Nano？**  
A: 运行 `python sayink_build/download_bundle_model_for_build.py`。

**Q: 识别不准？**  
A: 可试 FireRedASR2、Qwen3-ASR、FireRedASR2 AED；要快可换 SenseVoice。

**Q: 无法自动粘贴？**  
A: 管理员终端、密码框等会拦截；会提示「已复制」，请手动 Ctrl+V。

**Q: 以前装的是 VoiceInk，升级到 SayInk 会丢设置和历史吗？**  
A: 不会。SayInk 首次启动（或安装程序）会把 `~/.voiceink` 整体改名为 `~/.sayink`，设置、历史、日志和已下载模型原样保留；凭据管理器里的 API Key 在第一次读取时迁到新条目。若 `~/.sayink` 已存在则不会覆盖，旧目录保持不动。旧版 VoiceInk 还在运行时 SayInk 不会再开一个实例；首次启动会把注册表里旧的 VoiceInk 开机自启项删掉，换成 SayInk 的。

**Q: 历史会保存什么？如何关闭或清空？**  
A: 仅在本机 `~/.sayink/history.db` 保存文本历史与少量元数据（例如音频来源、模型、目标应用进程名，以及持续转写本场的说话人编号）；不保存音频，也不保存声纹。可在设置 → 通用 → 历史关闭未来写入；已有记录需在托盘 → 历史 中删除会话，或通过左侧摘要行的「清空全部历史」一次清除。清理策略按保留天数和最大会话数删除旧会话。

**Q: 如何切换浅色 / 暗色？**

A: 设置 → 通用 → 外观 → 主题。默认「暗色」；也可固定「浅色」或「跟随系统」。偏好写入 `~/.sayink/config.json` 的 `appearance.theme_mode`，重启后仍生效。

**Q: Linux / macOS 权限？**  
A: Linux 装 `xdotool`；macOS 在辅助功能中授权 SayInk。

**Q: 出问题了，日志在哪里？**  
A: `~/.sayink/logs/sayink.log`（自动轮转，最多约 4 MB）；程序异常崩溃的底层信息在同目录 `crash.log`。设置 → 关于 → 文件位置 可看到完整路径。

**Q: 怎么反馈问题或提建议？**  
A: 到 GitHub 的 [issue 页面](https://github.com/zyjhandsome/SayInk/issues/new/choose) 提交，有问题反馈和功能建议两个模板；报问题时附上最新一份 `sayink.log` 定位最快。

**Q: 再次双击 SayInk 图标没反应？**  
A: SayInk 同时只运行一个；再次启动会直接打开已在运行的主窗口。

**Q: 配置文件损坏了会怎样？**  
A: 启动时读不了 `config.json`，会先把它改名为 `config.corrupt-<时间>.json` 保留，再用默认设置启动，原来的设置不会被覆盖掉。某一节写错了类型（比如把 `"history"` 写成字符串）时，只有这一节回到默认值，其余设置照常生效。

**Q: 历史记录数据库损坏了会怎样？**  
A: 同样处理：`history.db` 改名为 `history.corrupt-<时间>.db` 保留，重新建一个空库，并在托盘提示一次。之前的记录不会显示，但文件还在，可以手动恢复。数据库完全打不开（被占用、没有权限）时不会动原文件，本次运行只是不保存历史，托盘和历史窗口都会说明原因。单条记录写入失败也会在托盘提示一次，细节在日志里。

**Q: 自动更新下载的安装包安全吗？**  
A: 只从 GitHub Releases 下载，先存为 `.part`，核对大小与 GitHub 公布的 SHA-256 后才会运行；不完整或校验不符的安装包会被删除并提示重试。GitHub 没有公布该安装包 SHA-256 时，SayInk 不会下载或自动安装，会提示到发布页手动下载。安装包目前没有代码签名，Windows 可能提示「未知发布者」。

**Q: 升级会不会重新下载模型？**  
A: 不会重新下载 Fun-ASR-Nano。自动更新下载轻量包（约 72 MB，含 CAM++ 和 Silero VAD）；安装目录里已有的 `models\` 和 `~/.sayink/models/` 里自己下载的模型都原样保留，升级后直接载入。只有卸载时选择「删除用户配置和模型数据」才会清掉。
