# SayInk — 语音转文字桌面工具

本地离线的**语音转文字**工具，提供 **单次转写、持续转写和会议** 三种模式。默认使用**单次转写**：按住快捷键说话，松开后识别并粘贴到光标处，可选大模型润色。**持续转写**启动后持续采集，按停顿分段输出。**会议**支持整场文字稿、说话人区分和会议纪要。采集**电脑播放声**或**混合音源**时，默认只记录到历史、不粘贴。音频在本机识别，默认不保存音频；可主动开启本机录音恢复。润色与纪要按配置调用大模型。

版本号以 **`sayink/version.py`** 中的 `__version__` 为准（当前 **2.2.29**）；安装包文件名、Inno 元数据与 Windows 下 `SayInk.exe` 属性均与之同步。

> **原名 VoiceInk。** 从 VoiceInk 升级：安装 SayInk 会先卸载旧版 VoiceInk，并把 `~/.voiceink`（设置、历史、已下载模型）整体改名为 `~/.sayink`，凭据管理器里的 API Key 也会自动迁移；无需重新配置或重新下载模型。

## 功能一览

### 三种模式

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **单次转写**（默认） | **按住**快捷键说话，**松开**后统一输出文字；录音中 **Esc** 取消。松开后转写条立即转为「正在识别」；上一句还没识别完时再按住会提示「请稍候」，不会把两句合并，此时按 Esc 也不会丢掉上一句 | 日常口述输入、短句、精确控制 |
| **持续转写** | **按住快捷键**开始持续采集；停顿后自动识别、输出；**Esc** 或转写条 **结束** 结束本次转写（进行中片段仍会完成） | 长口述、连续输入、播放内容整理 |
| **会议** | 从会议页或托盘**开始会议**，记录整场文字稿并区分说话人；结束后可整理文字稿、生成会议纪要，不自动粘贴 | 多人讨论、访谈、结构化会议记录 |

单次转写与持续转写在设置 → 通用中选择；会议从会议页或托盘单独开始。已有安装升级后保持原来的转写模式，默认值只影响新安装。术语约定见 [术语规范](docs/terminology.md)。

- 默认快捷键 **Alt+X**，左右 Alt 都可以；可在设置 → 通用 中更改。Windows 上按住快捷键时，主键（如 X）及其自动连发**不会**传给当前软件，Alt 组合松开时也不会激活菜单栏。因此 SayInk 运行时，Word / OneNote 里 Alt+X 的「Unicode 码转字符」会失效，需要这个功能请换成别的快捷键
- 若改用 **Shift+字母**（如 Shift+X）：**短按**（不到 0.18 秒）仍会正常输入大写字母，不会弹「录音过短」提示，左右 Shift 都可以，先松 Shift 再松字母也一样
- 为避免占用常用组合，Ctrl+C / Ctrl+V / Alt+Tab / Win+L 等不能设为录音快捷键
- 录制快捷键时支持字母、数字、Space 与 **F1–F12** 配合修饰键；录制中按 **Esc** 只是取消录制、保留原快捷键（Esc 本身用于取消 / 结束，不能作为录音键）
- 防误触：单次转写需按住约 **0.18 秒**，持续转写需按住约 **0.30 秒**；持续转写模式下**松开快捷键不结束**整场监听；短按不显示转写条
- **允许 Esc 结束持续转写**可在设置 → 通用 → 录音与输入 中关闭，此项仅在持续转写模式显示；关闭后在其他软件里按 Esc 不会中断监听，用转写条「结束」停止。结束后已录内容继续识别；按住录音时 Esc 则取消本次录音、不保留本次内容。转写条的提示和按钮说明会同步这一偏好
- **转写条位置**：单次转写仍短暂出现在屏幕上方；持续转写和会议默认贴在屏幕底部居中，避开 Word、PowerPoint 最大化时的功能区。可以拖动，松手后按屏幕记住相对位置，本场状态变化不会再把它拉回去；双击或右键「恢复默认位置」回到自动位置。预设在设置 → 通用 → 应用与历史（顶部居中、底部居中、右下角、上次拖动的位置）。持续转写和会议里，约 12 秒没有新文字会收起那一行转写，鼠标移上去再展开

### 技术栈复用情况

单次转写、持续转写和会议共用音频与识别的基础实现，按各自的会话、输出和保存规则工作。

| 能力 / 技术 | 单次转写 | 持续转写 | 会议 | 共用实现 |
|---|---|---|---|---|
| 音源与设备、重采样、混合音量配平 | 共用 | 共用 | 共用，可覆盖本场音源 | `AudioRecorder`、`audio_devices`、`audio_utils` |
| 语音检测与断句 | Silero / 能量法；默认停顿 1.2 秒 | 同左 | 同一断句器；默认停顿 1.5 秒 | `SpeechSegmenter`、Silero / 能量 gate；最长片段均为 15 秒 |
| 本地语音识别、模型加载与后台解码 | 共用 | 共用 | 共用，可覆盖本场模型 | `SpeechRecognizer`、`TranscribeWorker`、sherpa-onnx |
| 识别语言、术语热词与模型能力判断 | 按模型支持启用 | 同左 | 同一配置解析，可覆盖本场语言 | `RecognitionSettings` |
| ASR 标记清洗、文本规范化、术语大小写还原 | 共用 | 共用 | 共用 | `normalize_asr_output()`、`restore_glossary_case()` |
| 短句空结果重试、异常循环重识别 | 共用；仅对符合条件的片段有界重试 | 同左 | 同左 | `decode_asr_slice()`、`short_retry_audio()` |
| 说话人匹配与结束后聚类 | 不启用 | 共用 | 共用，另支持人工更正 | CAM++ / 频谱特征、`MeetingSpeakerSession`、`reassign_turns()`（逐段重新归属） |
| 片段内换人分段（实验性） | 不启用 | CAM++ 实际加载后启用 | 同左 | `SpeakerTurnDetector`、`TranscribeWorker` |
| 多人发言检测（实验性，默认关闭） | 不启用 | 开启开关且 CAM++ 与检测模型实际加载后启用 | 同左 | 疑似重叠不从长句中间切开，可匹配已有声音但不训练档案；短接话候选经声纹复核后拆分 |
| 顺序处理、输出与文本保存 | 松键后统一输出；历史按设置 | 分段输出；历史按设置 | 分段归档、不粘贴；文字稿始终保存 | `App` 处理队列与输出流程、`HistoryStore` / `MeetingStore`、SQLite |
| AI 服务调用 | 文字润色按开关 | 同左 | 会后纪要与原文精整，逐段润色默认关闭 | `llm_transport.chat_completion()`；会议可单独指定模型 |

共用实现不要求模式参数完全一致。会议保留暂停 / 继续、标记、文字稿更正和纪要流程；单次转写保持结束录制后统一输出。短句重试已覆盖三种模式，说话人判断和换人分段只在持续转写与会议中启用。详细边界见 [共用识别能力](docs/shared-recognition.md)。

### 音频与识别

| 来源 | 说明 |
|------|------|
| 仅麦克风 / 电脑声音 / 混合音源 | 16 kHz 单声道；设置中 **测试声音** 验证设备 |

- 引擎 **sherpa-onnx**（≥ 1.13.8），本地离线识别；内置 **9 款模型**，默认 **Fun-ASR-Nano**（约 950 MB）
- **已下载 ≠ 已载入**：每次冷启动须载入内存（Fun-ASR-Nano 约数十秒），等托盘「就绪」后再用。只有当前启用的模型会载入；再下载一个模型时，完成提示会说明它尚未启用，需在模型卡片点「使用此模型」切换
- 三种模式共用按停顿 **VAD 切分**；一口气说满 **15 秒**仍没有停顿时，优先在最近约 3 秒较安静处切开，找不到明显间隙时按时长切分，仍可能切到词中。强制分段后的短续音不再按独立短噪声过滤；切分后立即结束时，即使神经 VAD 尚未重新打开，也会在短暂起音缓存中检查并保留紧接切点的有声尾部。切点保持原规则，默认路径的原始采样范围不重叠。结束监听会 **flush 收尾句**。持续转写和会议在上一段润色或粘贴时，最多预先识别下一段；仍按原顺序润色、输出和写历史，预识别失败保留音频再走正常识别。单次转写仍在松键且所有片段处理完后统一输出。每段在切出时固定所属场次、序号和音频来源，结束后立刻开新场，上一场排队的片段仍写入上一场
- 持续转写与会议中，识别或润色跟不上说话时，默认在内存中排队；超过约 **3 分钟**会自动暂停监听并提示（会议仅暂停采集）。开启「录音恢复」且缓存健康时，约 2 分钟之后的排队音频转存磁盘，继续采集；写入失败或容量用尽时保留原有暂停保护。暂停期间的讲话不会补录；已录内容继续处理，会议积压清完会自动继续。单次转写不设 3 分钟暂停阈值，也可使用磁盘排队
- 监听中麦克风被拔掉或设备失效，约 3 秒内提示「音频设备已断开」，先送出已录尾音再停止采集；已切出的片段照常识别。驱动报告输入溢出时明确提示可能有录音缺口，继续接收后续声音；软件不能补回驱动未交付的采样
- 冷启动载入模型时，转写条显示该模型**上次载入用时**（首次为约 10–40 秒）
- **预期延迟（本机实测，CPU 推理，4 线程）**：Fun-ASR-Nano 的实时率约 **0.5–0.8**，即说 6 秒大约要算 3–5 秒；按住说话是松开后开始算，持续转写还要先等约 **1.20 秒**静音判定再开始算（不到 0.8 秒的短句会多等到约 1.8 秒，好和后面的话合成一段识别）。所以一句话说完到出字通常是 **几秒**，不是即时字幕。润色会再加一次大模型往返。数值来自一台 Intel Core Ultra 9 185H 笔记本，更慢的机器会按比例变长
- **（实验性）** 持续转写与会议共用谨慎的说话人匹配：只用清晰语音更新本场声音档案，证据不足时保留待确认。**历史**行上的时间是这段话开始的时间；在出现不同声音时显示「说话人 1」到「说话人 8」，已识别声音与未知段并存时标出「说话人待确认」；光标处粘贴仍是纯文字，关闭历史仍不保存转写内容。CAM++ 实际加载后，共用后台片段内换人检测，连续接话可按可靠边界分别转写，不完全依赖静音停顿；频谱回退仍按原有停顿分段。混合采集仅在来源可靠时标出麦克风或电脑播放。停止后按顺序处理剩余文字，再用可靠样本重新聚类；下一场重新编号。短促插话、重叠声音及噪声仍可能误判，不跨场保存声音档案。
- 单次转写、持续转写与会议共用 设置 → 通用 → **识别** 里的**识别语言**与**自定义词汇**（热词）；**语音分段**和说话人增强放在默认折叠的**高级识别设置**中。Silero VAD 成功加载后用于三种模式；未下载或加载失败会自动回退能量断句。高级设置明确显示**未下载 / 正在加载 / 已加载并生效 / 加载失败并回退**，可直接下载 Silero；引擎页的「已下载」仅表示文件存在。单次转写在内部按停顿分段识别，仍在松开快捷键后统一输出；持续转写与会议按段输出，默认停顿分别为 1.2 秒与 1.5 秒，最长分段都是 15 秒。分段时长保持现有默认。混合采集下三种模式都会自动配平两路音量。公共识别、辅助模型下载及模型切换在录音或处理语音期间会延后到本场结束、已录语音处理完成后生效，页面提示「已保存，待生效」；折叠高级设置后仍能看到等待状态或加载失败，不为应用这些更改中断采集或丢弃排队语音。共用能力与模式边界见 [`docs/shared-recognition.md`](docs/shared-recognition.md)
- **短句空结果重试（三种模式共用）**：不超过 8 秒的片段首次识别为空且有明显声音时，保留语音边界并补静音上下文重试一次；不改写有效文字，不对纯静音、极低音量或较长片段重试。重试本身不保存音频；失败后继续正常收尾。单次转写仍在松开快捷键且全部片段处理完后统一输出。重试会增加该片段的处理耗时，真实收益需用同一批真人录音对照评测，尚未提供准确率提升百分比。
- **跨段音频上下文（实验性，默认关闭）**：仅对提供可用词元时间戳的 CTC 模型，读取强制分段前后各最多 0.3 秒的上下文，按原始采样时间归属文字；严格验证完整文本覆盖，包括小数点与负号，失败就识别原片段。强制分段最多多等 0.3 秒；两份实际会议评测均未改善整体 CER，故不默认启用，设置页也不再提供这个开关。需要时才在配置 `stt.boundary_context_enabled` 里打开。Fun-ASR-Nano 等缺少时间戳的模型不启用此功能
- **轻声增强（默认关闭）**：通用 → 识别 → 高级识别设置，可用于安静环境中音量偏低的说话。需要实际加载 Silero；增强语音检测与 ASR 输入并降低有声底线，原始录音与声纹输入不变，数字静音仍拒绝。嘈杂环境可能增加误触发；能量断句回退时不启用。另对已有明显音量起伏的低音量 ASR 片段做有界音量归一化，不增加一遍模型解码
- **混合音源分别识别（实验性，默认关闭）**：通用 → 录音与输入，分别断句、识别麦克风与电脑声音，按原始采样时间排队，减少两路同时讲话时互相遮盖。它不能分离同一音轨内的两个人声；等待另一音轨较早的发言切出或两路都发言时，延迟及总解码量可能增加
- **录音恢复（默认关闭）**：通用 → 应用与历史，开启后从下一次录音开始，将 VAD 过滤前的录音写入本机 `audio-recovery/`；混合输入额外保留配平、回声扣除前的两条原始音轨。可查看、导出 WAV、在本机重新识别和另存文字，不自动粘贴，不发送给远程服务。正常结束的缓存在下次启用缓存时清理超过 7 天的录音；异常中断缓存需手动删除。录音缓存上限 2 GB，每场待识别队列另占最多 2 GB；磁盘余量低于约 128 MB 时停止写缓存并提示。写入队列有界、约每秒同步一次；异常退出可恢复已写完的采样，但最后尚未写入或同步的部分仍可能丢失，不能承诺断电零丢失。删除文字历史不会删除录音缓存，需在恢复窗口单独删除
- **多人发言检测（实验性，默认关闭）**：轻量包和完整包都带上这个模型（约 2 MB）。开关默认关闭，在 通用 → 识别 → 高级识别设置 打开后，与 CAM++ 一起从下一场持续转写或会议开始使用。安装目录里没有这份文件时，仍可在 设置 → 引擎 下载。检测到疑似重叠或未分开的多人时，保留原音频进行文字识别；长段重叠不再从句子中间切开。重叠部分可以匹配已经听清的声音，但不更新声音档案；已加载的检测器推理失败时也暂不判断。公共识别状态显示实际加载或加载失败。它不能分离重叠声音，仍会漏检，也可能增加待确认片段与耗时。CAM++ 的强证据可跨麦克风/电脑声音匹配，弱证据保留待确认；会后合并增加相互一致性约束，减少链式误并。验证记录见 [本轮优化](docs/recognition-optimization-20261020.md)。
- 结果自动去掉 `<asr_text>`、`<sil>`、`<|zh|>` 等识别器自身的标记；用户口述的 `<div>`、`<br>` 之类正常保留
- 文本清洗只移除已知 ASR 标记；真实重复句、连续强调以及中日 / 中韩混合句均保留。仅凭文字不能可靠区分真实表达与模型幻觉，因此偶发的模型重复或语言漂移也可能保留，重要内容仍需核对
- **异常循环重识别（三种模式共用）**：仅当文字超过宽松的音频承载长度预算，且同一短语循环至少 8 次时，用本段完整音频分成两片、保留少量交接上下文，再识别一次。正常重复、强调和数字不会仅因重复而被删除；候选为空、仍过长、异常或取消时保留首次结果。每段最多增加两次较短解码，不对普通片段重复识别，额外耗时计入评测实时率

|------|------|--------|
| **Fun-ASR-Nano**（默认） | 中/英/日与方言，支持热词和识别语言 | 950 MB |
| SenseVoice | 更快。中/英/日/韩/粤，支持识别语言 | 230 MB |
| Qwen3-ASR 0.6B | 多语种，支持热词 | 983 MB |
| FireRedASR2 | 中文和方言候选（CTC 分支） | 740 MB |
| FireRedASR2 AED | 中文和方言的较慢精度候选 | 1.2 GB |
| Paraformer 中文 | 小体积中英识别 | 240 MB |
| Paraformer 三语 | 中英粤；需要粤语时再选 | 240 MB |
| Zipformer CTC | 纯中文，无英文和热词 | 367 MB |
| Qwen3-ASR 1.7B | 多语种大参数版，较慢；权重来自第三方仓库 | 2.4 GB |

上表顺序就是引擎页、会议模型列表里的推荐顺序。「推荐」只标 Fun-ASR-Nano。精度 / 速度是目录内的相对评级，不是统一公开评测。准确率随口音、领域用词、麦克风和噪声变化很大；机器较弱或更在意出字速度时换 SenseVoice。想用数字说话，`tools/asr_bench.py` 可以在本机对几款模型跑同一组录音，输出字错率、热词命中率与实时率。默认先按会议的 Silero 断句再逐段识别，和开会时的切段一致（见 [`docs/asr-benchmark.md`](docs/asr-benchmark.md)）。说话人拆人 / 并人的标法见 [`docs/meeting-speaker-eval.md`](docs/meeting-speaker-eval.md)，目前还没有真人结果。

### 会议

独立于转写的「会议」流程：**托盘 → 开始会议**，或主窗口 **会议** 页右上角「开始会议」。设计依据见 [`docs/meeting-notes-design.md`](docs/meeting-notes-design.md)。

- **开始**：默认弹出一张信息卡（标题 / 参会人 / 议程 / 音频来源 / 识别模型 / 语言，全部可空），可在 设置 → 通用 → **会议默认设置** 关掉改为直接开始。会议音频来源默认**麦克风 + 电脑声音**，也可改为跟随转写设置，或单独指定仅麦克风、仅电脑声音；已有安装保存过的会议音源会保留。识别模型默认与转写相同。开始卡片会显示跟随的当前音源，卡片上的音源、模型和语言修改**仅用于本场**，不改写默认设置或共享识别配置
- **进行中**：转写条显示「会议中 · 计时」，左键点转写条打开会议页，「标记」按钮或会议页「标记此刻」记下重要时刻（可带备注）；会议页实时按说话人逐条显示文字，右侧可随手记笔记。会议期间 **转写快捷键暂停**（按了会提示「会议记录中」），**Esc 不会结束会议**；只能用转写条「结束」、托盘「结束会议」或会议页「结束会议」收尾。结束会先把排队的语音识别完再归档
- **文字稿**：每句话带相对时间戳与「说话人 N」，写入 `history.db`（`trigger_mode = meeting`），**即使关闭了转写历史也会保存**；不出现在历史页列表里，不受历史保留天数 / 最大会话数清理，也不被「清空全部历史」删掉——只能在会议页逐场删除。默认不保存音频，也不保存声纹；录音恢复须单独开启，缓存与文字稿分别删除
- **暂停与核对**：会议页可「暂停采集 / 继续采集」。手动暂停期间不采集新音频，已录内容继续识别，不会自动恢复；继续后仍是同一场会议。主窗口侧栏持续显示本场音源、录制或暂停状态及会议保存去向，切换页面后仍可查看。实时文字稿更新保留选区和阅读位置，停在底部时才跟随最新发言。`Ctrl+F` 在会后列表搜索会议，在进行中查找本场文字稿；搜索无结果提供清除入口。会议开始卡与笔记区支持滚动，小屏幕下开始、暂停、继续和结束操作保持可达
- **说话人**：**说话人嵌入 CAM++**（约 28 MB）用于持续转写与会议的说话人增强，**Silero VAD**（约 2 MB）用于三种模式的断句。公共识别页可开关 CAM++ 增强并查看实际加载或回退状态；单次转写无需区分说话人。第一次开会若还没下载，会问一次「下载后开始 / 直接开始」；之后开始卡片和进行中页面都保留「下载辅助模型」按钮（会中下载对下一场生效），引擎页也能下载。没下载或加载失败时退回频谱特征与能量断句；手动选能量断句或关闭 CAM++ 时不会误报模型缺失。持续转写与会议仅用清晰片段建立多段声音档案，短句证据不足、候选人接近或人数超出自动上限时保留待确认；较弱的连续性判断不更新档案。一场结束时对全部发言重新聚类并逐段归属：在线时被拆开的同一个人会合并，归错的单句会移回正确的人，用户命名或更正过的保持不变；声音档案只在本场内存中存在，不跨场识人。会议页可把「说话人 2」改成称呼，文字稿与纪要同步替换
- **识别参数**：术语表（最多 50 条、每条 20 字）会作为**热词**传给支持的模型（Fun-ASR-Nano、Qwen3-ASR）；识别语言会传给支持的模型（Fun-ASR-Nano、SenseVoice）。两者对转写同样生效。不支持的模型只把术语交给纪要模型。无论哪个模型，识别结果里只是大小写不同的英文术语（如 FireRedASR2 输出的 `GITHUB`）都会改回术语表的写法。一行写成 **`词=误写1、误写2`**（如 `张鑫=张新、张欣`、`五证=五中`）时，等号后面是这个词常被听成的写法：识别结果里出现这些误写会被**直接改回**正确的词（英文整词、不分大小写；中文按原样匹配），不走网络、不加延迟；热词仍只传正确写法。每个词最多 5 个误写，误写也不超过 20 字。会议段落**不逐句润色**（`meeting.polish_segments`，默认关）
- **纪要**：会议结束后在会议页选模板（通用 / 站会 / 一对一 / 客户沟通 / 评审）点「生成纪要」。使用 设置 → AI 服务 → 接口配置 的地址与密钥（与润色共用，关闭润色时也一直可填），可在 AI 服务 → 会议纪要 单独指定更大的模型并测试连接、设默认模板与输出语言；不需要开启「文字润色」。没配置时会议页的按钮显示「配置 AI 接口」，点击直接跳到接口配置。会议页与 AI 服务页的「管理模板」支持新建、复制、编辑、删除自定义模板，可配置名称、整理要求、输出形式与章节；内置模板可复制后修改。远程端点第一次生成前会确认（只发文字稿，不发音频），确认后记住该地址。超过约 1 万字的文字稿分块生成再合并；纪要里找不到文字稿依据的内容标「（待核对）」，没内容的小节写「本场未识别到」
- **会后自动生成**：AI 服务 → 会议纪要 可打开「会议结束后自动生成纪要」（`meeting.auto_generate`，默认关）。打开时若是远程端点会先确认一次；之后每场结束、文字稿满 200 字就按默认模板在后台生成，主窗口没打开时完成或失败会托盘提示。纪要一次只生成一场：连续多场会按结束顺序排队，会议列表标出「纪要排队中 / 生成中 / 生成失败」；另一场正在生成时手动点「生成纪要」会排到自动任务前面，不打断当前那场；排队中可「取消排队」。网络、超时、限流或服务端 5xx 失败时 1 分钟、5 分钟后各自动重试一次，密钥、余额或地址未确认等问题不重试，会议页显示原因，点「生成纪要」手动再试。用本机模型（`localhost` 等）时，会议进行中不跑自动任务，新会议开始会让出正在跑的自动任务，结束后从已完成的分段继续。退出或崩溃后，排队的任务下次启动继续。已有纪要（包括手写的）不会被自动任务覆盖
- **原文精整**：会议模板可选「原文精整」，点击「整理原文」将多人的原始转写逐段、逐句融合为通顺、逻辑清晰的书面文章。保留业务细节、情绪、主观评价、个人口吻、条件及不同观点，仅去除口吃重复、纯粹口语赘词和无效寒暄；按人物、规划和话题变化细致分段，不按说话人或识别切片机械分段，不反复添加「某某表示」等转述套语，不生成摘要、标题或列表，始终保留原文语言。与纪要共用接口和模型，不需要开启文字润色。长文分块精整后直接拼接，不再摘要合并；检查来源片段覆盖、数字与单位、英文名称、否定和条件表达及明显压缩，输出截断或检查失败时重试一次，仍失败则保留当前版本并提示。规则检查不能保证完全无损，人名、观点归属等重要内容仍应对照文字稿核对。生成后可编辑、复制精整正文、导出；与纪要共用当前结果位置，重新生成会替换当前内容，可恢复上一版，模板与模型信息同步恢复。
- **阅读与核对**：纪要显示「AI 生成 / 已手动编辑」和所用模板；时间戳跳到对应文字稿并高亮，可「返回纪要」回到原阅读位置。连续发言按说话人归组，姓名明确标注为手动命名。空的决策 / 待办章节在阅读时收为简短提示，导出保留原文。
- **说话人纠错**：录制中、暂停时或会后均可「命名说话人」，也可直接点击实时文字稿中的姓名；同组已有发言及后续归入本组的发言同步使用姓名。「纠正发言人」可把已出字的某一段改归其他说话人或新增身份，只修改本段已有归属；会中保存成功后，近期清晰声音可帮助后续自动匹配，短句或无效声音不训练档案。已更正段落显示「归属已更正」，保存失败保留选择供重试。会议收尾整理或纪要生成时暂不可修改。人工命名与段落更正会保留，会后自动分组不会合并两个已手动确认的身份，也不会覆盖单段更正；已有纪要保留并提示核对，重新生成后更新来源状态。
- **片段内换人检测（实验性）**：会议与独立持续转写在 CAM++ 实际加载后，共用后台换人分析，再分别识别和归档；多人接话不再完全依赖静音停顿。声音过短或证据不稳定时仍可能待确认；检测失败保留完整语音继续识别文字。分段保留原始音频范围及相对时间，不回写已保存的人工修改。当前不分离同时说话的声音，不跨场识人。评测工具可分别对照换人边界、说话人归属与文字错字率。
- **修改文字稿**：会议结束且生成未运行时，文字稿每段旁的「编辑」可修正错字、人名、日期或数字；弹窗可查看、恢复修改前原文，点「保存修改」后生效。修改单独保存，保留识别原文、时间和说话人，已改段落显示「已修改」。后续生成纪要、原文精整、搜索、复制和导出使用修正内容；已有结果保留并提示核对、重新生成。保存失败时弹窗保留草稿，空白内容不能保存。
- **编辑与导出**：纪要用「保存修改」明确保存，切换会议、离开页面或开始新会议前也会自动保存；保存失败时留在会议页，草稿和提示都还在，不会切到别的页面。复制按钮随当前内容显示「复制纪要 / 复制文字稿 / 复制草稿」，文字稿不依赖生成纪要即可复制。导出可选仅纪要、仅文字稿或完整会议记录，文件格式可选 Markdown、纯文本或 SRT 字幕（SRT 按文字稿时间戳生成），编辑中使用当前草稿。模板选择表示下次生成使用的模板，刷新保留选择，重新生成仍有替换确认并可在「更多 → 恢复上一版纪要」找回上一版；标题可在会议页改。
- **异常**：设备断开或识别积压过长时**暂停采集而不结束会议**，会议页可「继续采集」；积压处理完会自动继续。程序崩溃时未结束的会议下次启动标记为「已中断」，仍可生成纪要。会议进行中退出程序会单独确认
- 会议期间保存的音频 / 引擎设置、托盘切换模型都会等会议结束后再生效

### 输出与润色

- **结果去向**（设置 → 通用 → 录音与输入，与音频来源相邻）：可选「自动（随音源切换）」「输入当前光标」「仅保存到历史」。单次转写和持续转写各自记住选择，控件会写明当前是哪一种，另一种保持自己的选择。升级前已经选定的固定去向会同时用于两种模式。自动模式下，麦克风默认输入光标，电脑声音或混合音源默认仅保存历史，并在控件旁显示当前实际去向；两种固定选择都会在切换音源与重启后保留，可随时重新选择自动。仅保存历史但历史已关闭时，就地显示不会保存的原因及「开启转写历史」按钮，转写条同步提示「未保存 · 历史已关闭」。剪贴板恢复选项只在输入光标时可用
- **声音测试**临时采集约 2 秒，不保存音频或转写文本；显示本次实际打开的设备、输入音量，以及无输入、音量偏低、偏高或设备错误。混合输入的总体有声结果不代表两路都成功，降级提示会保留。切换音源或设备后会清除旧的测试结论；「设备恢复自动选择」只重置设备，不修改音源或结果去向
- **自动粘贴**到光标处；无法确认成功时降级为「已复制到剪贴板」（不误报「已输入」）。目标窗口以管理员权限运行时（系统会拦截模拟按键），直接提示「已复制」，不发送粘贴键
- 发送粘贴键前会再次确认前台仍是开始输出时的窗口；等待期间切到了别的窗口，就不发送粘贴键，只把文字留在剪贴板供手动粘贴，避免误输入到新窗口
- Windows 上发送 Ctrl+V 时，若快捷键里的 Shift / Alt / Win 还被按着，会先抬起再补回，避免被目标软件当成 Ctrl+Shift+V 等别的组合
- 「已发送」表示已发送粘贴快捷键，无法证明目标控件已插入文字；请核对目标应用。粘贴键发出后前台窗口随即变了，则提示「已发送 · 未确认」并把文字留在剪贴板。macOS / Linux 的粘贴命令返回失败时会降级为「已复制」
- 润色或粘贴卡住超时：润色阶段卡住就直接输出 ASR 原文；粘贴阶段卡住则提示「输出超时 · 已复制」，文字在剪贴板，可手动 Ctrl+V。两种情况都会继续处理排队的下一段
- 「粘贴后恢复剪贴板」在粘贴约 0.5 秒后才恢复，且只恢复文本；原剪贴板是图片等非文本内容时保留转写文字，不会清空
- 可选 **OpenAI 兼容 API** 润色（DeepSeek、通义、Ollama 等）；失败，或返回内容明显比原话长很多（像在回答而不是润色）、删改了原话里的数字（阿拉伯数字含零；「三万五」等中文数字换算后比对，单独的「一」不算）、少了否定词（不 / 没 / 别 / not 等）、丢掉了英文专名（如 GitHub、API）时，**输出 ASR 原文**。数字检查允许时间补 `:00`、千位分隔符和小数末尾零等格式变化。这是保守的规则检查，拦不住所有改义（例如中文人名被改写），重要内容请核对
- AI 服务页的「文字润色」有两种**处理方式**：**润色**（默认，去口语赘词、补标点、理顺语序）和**纠错**（只改同音 / 近音错别字和自定义词汇里术语的写法，其余一字不动，口语赘词也保留）。纠错把术语表（含误写）和上一句的结尾一起交给模型参考，温度为 0；对 DeepSeek 官方的 `deepseek-flash` / `deepseek-v4-pro` 会关闭思考，一句话的往返通常不到 1 秒。纠错结果除了上面的数字 / 否定 / 英文专名检查，还必须和原文长度相近且改动不超过约两成字符，否则**输出原文**——所以模型顺手删了「嗯、那个」或改写了句子时，用户拿到的是识别原文而不是改写版。远场会议录音上这条链路对字错率的影响在 ±0.3 个百分点内（见 [`docs/recognition-optimization-round7-20261021.md`](docs/recognition-optimization-round7-20261021.md)），它的价值是术语写法和明显的同音错字，不是整体准确率
- 单次转写模式下，上一句还在润色时可以开始录下一句；上一句润色失败时仍回退它自己的原文，不会被下一句影响
- Windows 上 API Key 保存在**系统凭据管理器**（「SayInk/llm.api_key」），不写入 `config.json`；旧版本配置里的 Key 会在启动时自动迁移。凭据管理器写入失败或读不出来时，Key 只在本次运行中有效，`config.json` 里残留的明文 Key 也会被清掉，AI 服务页会提示重启后需重新填写
- **主窗口**（侧栏：历史 / 会议 / 通用 / 引擎 / AI 服务 / 关于）收纳设置、历史与会议记录；转写只留一条薄 **转写条**。托盘与转写条共用 模型载入中 / 正在听 / 正在识别 / 润色中 / 已复制 / 会议记录中。托盘 → **打开 SayInk**（单击或双击托盘图标均可打开主窗口）；配置保存在 `~/.sayink/config.json`

| **跟随系统** | 按 Windows 浅/深色外观解析有效主题 |

- 入口：**设置 → 通用 → 外观 → 主题**；偏好键 `appearance.theme_mode`（`system` / `light` / `dark`）
- 一次作用于主窗口、转写条、托盘菜单（含全局控件样式）
- 设计令牌权威源见 [`design-system/MASTER.md`](design-system/MASTER.md)；实现位于 `sayink/ui/design_tokens.py`、`theme.py`

### 工作台操作

- 主窗口侧栏显示当前运行状态、音源与触发方式；设置页提供即时保存提示。
- 从托盘退出或安装更新时，若仍在录音、识别、润色或有片段排队，会先询问。默认「返回继续处理」，Esc / 关闭确认框也会返回；可结束监听并等剩余内容处理完成后再退出。「放弃并退出」会丢弃尚未完成的内容。空闲退出不弹确认。取消更新安装后，已下载的包会保留，再次安装会重新校验 SHA-256，校验通过即可复用。
- **Ctrl+1…6** 切换六个页面，**Ctrl+F** 搜索历史，**Ctrl+W** 收到托盘；录制新快捷键时暂停这些导航快捷键。
- 双击标题栏最大化 / 还原，拖动任意窗口边缘或右下角调整窗口；历史页中间分隔条可调整阅读宽度。
- 历史按天分组，列表上方可**搜索全部转写历史**（原文与润色文本，不含会议）；结果预览显示命中段落和附近内容，首次打开命中关键词的版本。每条会话展示两行正文预览，模型等参数收在「详细信息」。超过 50 场可继续加载更早会话，搜索结果同样每 50 条一页（显示「找到 50+ 条」并可加载更多），搜索与选中会话在刷新后保留。
- 点「选择」进入带复选框的批量模式，也支持 **Ctrl / Shift 多选**；摘要与复制 / 导出 / 删除按钮均显示已选数量，并可一键 **合并** 多条会话（8 秒内可撤销）或 **转为会议** 进入会议工作台生成结构化纪要。「完成」返回单条预览。批量复制按时间从早到晚合并最终文本（有润色用润色版）。单条会话支持 **编辑**（保存为润色文本，原文保留不变）、事后 **润色 / 重新润色**（按「AI 服务」里的处理方式执行，选「纠错」时按钮即为「纠错」；与实时输出同样使用自定义提示词、术语表和保真检查，未通过检查的结果不会保存）以及在「更多」菜单中 **转为会议并整理**。有润色结果时可切换「润色 / 原文」，**唯一的主复制按钮和 Ctrl+C 都复制当前查看的版本**；在正文中选中文字时 Ctrl+C 仍只复制所选部分。
- 单条删除位于详情「更多」菜单，也支持 **Delete**；删除或合并后 8 秒内可在底部提示条撤销。「清空全部转写历史…」位于列表「更多」菜单，确认框显示总条数，并明确包括未加载和搜索结果之外的记录、会议不受影响以及不可撤销。

### 历史

- 默认开启「保存转写历史」；首次使用会询问，默认选择开启。关闭后只停止未来写入，不删除已有记录
- 历史写入发生在文本输出流程之后；保存移除引擎标记后的 ASR 原文，以及术语替换 / 大小写还原 / 润色后的输出文本（如有变化），便于核对修改前后；另存音频来源、触发模式、模型、时长与目标应用**进程名**。持续转写的多人场次另存本场说话人编号（最多 8 人；一场结束后会按整场重新聚类改写一次），不写入粘贴文本，也不跨场保留声纹
- 托盘 → **历史** 打开主窗口并切到历史，可搜索、查看、复制原文 / 润色结果、删除会话，并导出 Markdown
- 历史保存在 `~/.sayink/history.db`（SQLite）；按「整场会话」管理，默认保留 **90 天**、最多 **5000 场**
- 会议的文字稿、标记、说话人名与纪要在同一个数据库里，但由「会议」页单独管理，不计入上面的清理与清空（见 [会议](#会议)）

## 快速上手

### 安装（Windows，推荐）

[Releases](https://github.com/zyjhandsome/SayInk/releases) 提供两种安装包，选一个即可：

| 安装包 | 大小 | 适合 |
|--------|------|------|
| **`SayInk-Setup-2.2.29.exe`**（轻量包，默认） | 约 81 MB | 首次安装、日常更新。已带说话人嵌入 CAM++、Silero VAD、多人发言检测（实验性）及其所需的 onnxruntime。不含 Fun-ASR-Nano，首次启动的准备页会在本页下载默认模型（约 950 MB，只需一次），并可先测麦克风；引擎载入完成前不能试说。其他模型仍可到 **设置 → 引擎** 下载 |

### 首次使用

1. 等托盘 **「模型载入中」** 消失；持续转写模式就绪后**不会**再弹闲置「待开始」，请看托盘提示
2. 托盘 → **打开 SayInk**（Windows **双击**托盘打开主窗口；冷启动第一次落在「通用」）→ **测试声音**；确认触发方式
3. **单次转写**（默认）：按住 **Alt+X** 约 **0.18 秒** 说话 → **松开** 识别并粘贴
4. **持续转写**（可选）：设置 → 通用 切换后，按住 **Alt+X** 约 **0.30 秒** → 说话停顿约 **1.2 秒**后自动出字（不用点结束）→ **Esc** / 转写条 **结束**整场

### 操作指南

| 操作 | 单次转写（默认） | 持续转写 |
|------|------------------|----------|
| **按住快捷键** | 开始录音 | 开始整场监听 |
| **松开快捷键** | 结束并识别 | 不结束监听 |
| **Esc** | 取消录音 | 结束整场（可在设置中关闭） |
| **转写条「结束」** | 无此按钮（松开即出字，转写条随后自动收起） | 结束整场 |

> **快捷键无反应？** 确认不在「模型载入中」；持续转写需按住约 0.30 秒。默认 **Alt+X**，可在设置中更改。会议进行中快捷键会被暂停，转写条会提示「会议记录中」。

**会议记录：** 托盘 → **开始会议**（或主窗口 会议 页）→ 填信息卡（可跳过）→ 开会；需要时点转写条「标记」→ 转写条「结束」/ 托盘「结束会议」→ 会议页选模板点 **生成纪要**（或在 AI 服务 → 会议纪要 打开会后自动生成）→ 编辑 / 复制 / 导出。

**AI 服务（可选）：** 设置 → AI 服务 → 接口配置，填 API URL / Key / 模型名；文字润色与会议纪要共用这组配置，可分别开启。接口地址以 `http://` 或 `https://` 开头即可（无论是否开启润色，保存时都会检查；其它协议会被拒绝）。公网 HTTP 会明文传输密钥和转写内容。公网地址请填写 Key；本机或局域网端点（`localhost`、`127.0.0.1`、`192.168.x.x` / `10.x.x.x` / `172.16–31.x.x`、`*.local`，如 Ollama `http://localhost:11434/v1`）Key 可留空（留空时不发送 `Authorization` 请求头）。  
**历史（可选）：** 设置 → 通用 → 历史，可开关「保存转写历史」，并调整「保留天数」与「最大会话数」。关闭开关只停止未来写入，不会删除已有历史。

**外观：** 设置 → 通用 → 外观，可选跟随系统 / 浅色 / 暗色；切换后立即作用于主窗口、转写条与托盘。

**模型目录：** 设置 → 引擎 → 存储位置 **更改**（默认 `~/.sayink/models/`；安装版的安装目录普通用户不可写时，新下载的模型一律放到这里，安装包自带的模型仍可直接使用）。  
**下载源：** 设置 → 引擎 → 下载 → 下载源。默认「自动」先连 Hugging Face 官方，连不上时改用 hf-mirror 国内镜像；也可固定其中一个。每个模型都锁定在模型仓库的某个固定提交上，每个文件下载后都要核对大小和 SHA-256（固定值写在 `sayink/speech_recognizer.py` 的模型表里）：不完整或内容不符的文件不会保留；自动模式下会改从另一个来源重下。

## 从源码打包

**Windows 10/11**，Python 3.10+。生成安装包还需 [Inno Setup 6](https://jrsoftware.org/isdl.php)。默认打出的是**轻量包**（带说话人嵌入 CAM++、Silero VAD 和多人发言检测（实验性），不含 Fun-ASR-Nano）；加 `--with-model` 打**完整包**，再带上 **Fun-ASR-Nano**。两种包装前，对应模型都要已在本地。

```bash
pip install -r requirements-build.txt -c constraints-windows-py310.txt   # 运行依赖 + PyInstaller，按已验证版本固定
python -m sayink_build.dependency_check                 # 打包前检查依赖版本
python sayink_build/download_bundle_model_for_build.py   # 把 Fun-ASR-Nano、CAM++、Silero VAD、多人发言检测下载到 ./models/
python build_release.py                 # → dist/SayInk-Setup-<版本>.exe（轻量包，约 81 MB，含 CAM++、Silero VAD 和多人发言检测）
python build_release.py --with-model    # → dist/SayInk-Setup-<版本>-full.exe（完整包，再含 Fun-ASR-Nano）
# 或仅便携版：
python build.py                         # → dist/SayInk/SayInk.exe（须整目录分发；加 --with-model 再带 Fun-ASR-Nano）
```

`build_release.py` 打包前会做发布检查（`sayink_build/release_gate.py`）：已跟踪文件没有未提交改动、源码目录没有未跟踪文件；远端 `v<版本>` tag 指向当前提交；该提交的 `tests.yml` CI 已通过。任何一项不满足就停止打包。所以发版顺序是：提交并推送 → 等 CI 变绿 → 打 tag 并推送 → 打包 → 上传。本地试打包加 `--skip-release-checks`，这种产物不得发布。

发布时把两个安装包都上传到同一个 Release；应用内更新器按文件名 `SayInk-Setup-<版本>.exe` 挑轻量包（`sayink/updater.py`），找不到时才退回同版本的其他安装包。便携版须整目录分发 `dist/SayInk/`。

## 变更审查清单（必读）

> **规则：** 每次功能新增、行为修改或 Bug 修复合并前须：读 diff → 确认本 README 用户向描述仍准确 → 核对架构/信号未破坏 → 跑测试 → 手工冒烟 → 在 PR 中记录结论。不得只改代码不更新文档，不得只改文档不跑验证。

**最低验证：**

```bash
py -3.10 -m pytest tests/test_readme_features.py tests/test_theme_resolve.py tests/test_ui_styles.py -q
```

**全量测试与验证环境：** Windows x64 / Python 3.10 使用已验证的固定依赖约束：`python -m pip install -r requirements-dev.txt -c constraints-windows-py310.txt`。其他平台使用 `requirements-dev.txt`。设置 `QT_QPA_PLATFORM=offscreen`，运行 `python -m pytest -p no:cacheprovider tests -q`。`tests/conftest.py` 让整个测试会话跑在英文 Windows 代码页（cp1252，与 CI 运行机相同）上，并把用户目录和 `%APPDATA%` 指向临时目录：中文开发机上的结果与 CI 一致，测试也不会读写真实的 `~/.sayink`。唯一加载真实模型的检查（Silero VAD）默认跳过；想在本机跑，把 `SAYINK_REAL_MODELS_DIR` 设为应用的模型目录（如 `%USERPROFILE%\.sayink\models`），它只读取、不写入。

GitHub Actions 的 `.github/workflows/tests.yml` 会在 push / PR 时执行 `ruff check`（配置见 `ruff.toml`，只查语法错误、未定义 / 未使用名称等硬错误）、Windows 回归、`pip check` 与发布依赖检查。本地可用 `python -m ruff check sayink sayink_build tests build.py build_release.py run.py`。`python -m sayink_build.dependency_check` 核对当前环境与 `requirements.txt`；`build.py` 也会先检查依赖，再清理旧构建目录，低于要求的引擎不能继续打包。固定约束覆盖 Python 包版本，不包含 Windows 系统组件或安装包签名；模型权重另由模型表里的固定提交和 SHA-256 锁定，`build.py` 打包前会逐个校验这次要带上的模型文件。

记录结论时写明 Python、PyQt6、sherpa-onnx 版本：sherpa-onnx 低于下限（1.13.8）的环境只能证明测试里的应用逻辑，不能代表发布依赖。发版前仍应在干净环境中跑全量测试，并冒烟安装包。当前可靠性优化与验证记录见 [`docs/reliability-first-pass.md`](docs/reliability-first-pass.md)。

| **P0** | 粘贴不假成功（含管理员窗口）；等待期间焦点切走不发送粘贴键；持续转写模式收尾句不丢；开启润色时持续转写模式逐段输出、不丢段不串段，排队片段不串场；润色失败或数字被删改时回退本句原文；未完成转写退出须明确确认放弃，安装更新不能先启动安装包再确认；API Key 任何情况下不以明文写入 `config.json`；自动更新必须有 SHA-256；加载中不被其它错误盖住；发行版日志写入 `~/.sayink/logs`；会议：默认不保存音频、始终不保存声纹；录音恢复须显式开启，文字稿不随历史清理 / 清空丢失，Esc 与转写快捷键不会结束会议，会议文字只进历史库不粘贴，纪要只发文字稿且远程端点首次需确认 |

## 常见问题

**Q: 选好模型了，为什么启动还要等很久？**  
A: **下载/选好** ≠ **载入内存**；默认 Fun-ASR-Nano 冷启动约数十秒。等托盘「就绪」再按热键。

**Q: 托盘已就绪，转写条还在加载？**

A: 正常应同步；以转写条为准，加载完成前勿按热键。

**Q: 如何转写电脑播放的声音？**  
A: 设置 → 通用 → 录音与输入，音频来源选「电脑声音」或「混合音源」。结果去向为自动时，会仅保存到历史，在历史页看结果；需要输入光标时，在相邻的「结果去向」中固定选择「输入当前光标」。Windows 建议 `PyAudioWPatch` 或立体声混音 / VB-Audio。

**Q: 持续转写怎么用？**

A: 设置 → 通用 → 录音与输入 选「持续转写」。按住 **Alt+X** 开始；说话停顿约 **1.2 秒**后自动输出，不用点结束；**Esc** 或转写条 **结束** 停止整场。开会选「混合」并配合「仅保存到历史」。

**Q: 开会想要一份纪要，该用持续转写还是会议记录？**  
A: 用 **会议记录**（托盘 → 开始会议）。持续转写只是把话写进历史；会议记录会带时间戳、区分说话人，结束后一键生成纪要，期间转写快捷键和 Esc 都不会误碰停掉。纪要用的是 设置 → AI 服务 里的大模型接口（不用开启润色），没配置也能先保存文字稿，配好后再生成。连着开好几场的话，可在 AI 服务 → 会议纪要 打开「会议结束后自动生成纪要」，每场结束后按默认模板在后台逐场生成。

**Q: 会议纪要里的「（待核对）」是什么意思？**  
A: 模型写的这句在文字稿里找不到对应原话，可能是概括过头或听错。核对后可直接在会议页编辑纪要，或换个模板重新生成。

**Q: 会议没区分出说话人 / 把一个人拆成了两个？**  
A: 2.2.7 起轻量包和完整包都带上 CAM++ 和 Silero VAD。更早的轻量包要在开始卡片或进行中页面上点「下载辅助模型」（约 30 MB），或到 设置 → 引擎 下载；下一场会议和下一场持续转写都自动启用。没有它时只能按频谱粗分，同一个人换个说法、音量一变就可能拆成两个编号。持续转写与会议共用清晰样本档案，较弱的连续性判断只有证据足够时才沿用上一位，过短或有歧义的声音保留待确认；整场处理完再对全部发言重新聚类、逐段归属。实际加载 CAM++ 后才会进一步分析片段内换人，短促插话和同时说话仍可能误判。会议页可把编号改成称呼，文字稿和纪要会一起改。

**Q: 会议中电脑卡了、麦克风掉了，内容会丢吗？**  
A: 已识别的句子已经在本机数据库里。设备断开或识别积压太长时只暂停采集，会议页点「继续采集」即可；程序崩溃的话下次启动这场会标为「已中断」，仍可生成纪要。

**Q: 说完要等几秒才出字，正常吗？**  
A: 正常。识别在本机 CPU 上跑，实时率约 0.5–0.8：6 秒的话大约算 3–5 秒；持续转写还要先等约 1.2 秒静音确认这句说完。开着润色会再加一次大模型往返。想更快可以换更小的模型（设置 → 引擎）或关闭润色。

**Q: 混合模式只有麦克风？**  
A: 刷新设备列表，检查系统声设备；测试时同时说话并播放电脑声音。

**Q: 短按快捷键没反应？**  
A: 单次转写需按住约 **0.18 秒**，持续转写需按住约 **0.30 秒**；短按不会进入。

**Q: 持续转写在有风扇声 / 底噪的环境里一直不出字，或者每隔 15 秒才出一大段？**  
A: 分段门限会跟着最近约 8 秒里最安静的时刻自动抬高（最多到固定上限），稳定的底噪不再被当成一直在说话；不到 0.2 秒的敲键、咳嗽等瞬响也不会单独成段。若环境噪声本身就接近说话音量，请靠近麦克风或降低噪声。

**Q: 结果里有 `<asr_text>` / `<sil>`？**  
A: 应自动清洗；若仍出现请升级至最新版。

**Q: 打包提示缺少 Fun-ASR-Nano？**  
A: 运行 `python sayink_build/download_bundle_model_for_build.py`。

**Q: 识别不准？**  
A: 默认已是 Fun-ASR-Nano。要更快出字可换 SenseVoice；多语种且要热词可试 Qwen3-ASR 0.6B。FireRedASR2 是中文方言候选，本机远场会议实测不如默认；FireRedASR2 AED 更慢，尚未在同一条链路上测过。

**Q: 无法自动粘贴？**  
A: 管理员终端、密码框等会拦截；会提示「已复制」，请手动 Ctrl+V。

**Q: 以前装的是 VoiceInk，升级到 SayInk 会丢设置和历史吗？**  
A: 不会。SayInk 首次启动（或安装程序）会把 `~/.voiceink` 整体改名为 `~/.sayink`，设置、历史、日志和已下载模型原样保留；凭据管理器里的 API Key 在第一次读取时迁到新条目。若 `~/.sayink` 已存在则不会覆盖，旧目录保持不动。旧版 VoiceInk 还在运行时 SayInk 不会再开一个实例；首次启动会把注册表里旧的 VoiceInk 开机自启项删掉，换成 SayInk 的。

**Q: 历史会保存什么？如何关闭或清空？**  
A: 仅在本机 `~/.sayink/history.db` 保存文本历史与少量元数据（例如音频来源、模型、目标应用进程名，以及持续转写本场的说话人编号）；默认不保存音频，也不保存声纹。录音恢复为独立的可选本机缓存，默认关闭；开启后需在恢复窗口管理音频。可在设置 → 通用 → 历史关闭未来写入；已有记录需在托盘 → 历史 中删除会话，或通过左侧摘要行的「清空全部历史」一次清除。清理策略按保留天数和最大会话数删除旧会话。

**Q: 如何切换浅色 / 暗色？**

A: 设置 → 通用 → 外观 → 主题。默认「暗色」；也可固定「浅色」或「跟随系统」。偏好写入 `~/.sayink/config.json` 的 `appearance.theme_mode`，重启后仍生效。

**Q: Linux / macOS 权限？**  
A: Linux 装 `xdotool`；macOS 在辅助功能中授权 SayInk。

**Q: 出问题了，日志在哪里？**  
A: `~/.sayink/logs/sayink.log`（自动轮转，最多约 4 MB）；程序异常崩溃的底层信息在同目录 `crash.log`。设置 → 关于 → 文件位置 可看到完整路径。

**Q: 怎么反馈问题或提建议？**  
A: 到 GitHub 的 [issue 页面](https://github.com/zyjhandsome/SayInk/issues/new/choose) 提交，有问题反馈和功能建议两个模板；报问题时附上最新一份 `sayink.log` 定位最快。

**Q: 再次双击 SayInk 图标没反应？**  
A: SayInk 同时只运行一个；再次启动会直接打开已在运行的主窗口。

**Q: 配置文件损坏了会怎样？**  
A: 启动时读不了 `config.json`，会先把它改名为 `config.corrupt-<时间>.json` 保留，再用默认设置启动，原来的设置不会被覆盖掉。某一节写错了类型（比如把 `"history"` 写成字符串）时，只有这一节回到默认值，其余设置照常生效。

**Q: 历史记录数据库损坏了会怎样？**  
A: 同样处理：`history.db` 改名为 `history.corrupt-<时间>.db` 保留，重新建一个空库，并在托盘提示一次。之前的记录不会显示，但文件还在，可以手动恢复。数据库完全打不开（被占用、没有权限）时不会动原文件，本次运行只是不保存历史，托盘和历史窗口都会说明原因。单条记录写入失败也会在托盘提示一次，细节在日志里。

**Q: 自动更新下载的安装包安全吗？**  
A: 只从 GitHub Releases 下载，先存为 `.part`，核对大小与 GitHub 公布的 SHA-256 后才会运行；不完整或校验不符的安装包会被删除并提示重试。GitHub 没有公布该安装包 SHA-256 时，SayInk 不会下载或自动安装，会提示到发布页手动下载。安装包目前没有代码签名，Windows 可能提示「未知发布者」。

**Q: 升级会不会重新下载模型？**  
A: 不会重新下载 Fun-ASR-Nano。自动更新下载轻量包（约 81 MB，含 CAM++、Silero VAD 和多人发言检测）；安装目录里已有的 `models\` 和 `~/.sayink/models/` 里自己下载的模型都原样保留，升级后直接载入。只有卸载时选择「删除用户配置和模型数据」才会清掉。
